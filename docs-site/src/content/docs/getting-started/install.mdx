## Requirements

- **git 2.31 or newer** on your `PATH`. tt-git runs the `git` you already
  have for everything, so it follows your config, hooks, `.mailmap` and
  credential helpers. Marking [branches that conflict with the base
  branch](/panes/branches/#conflicts-with-the-base-branch) needs git 2.40.
- A terminal with true color and Unicode box drawing. Windows Terminal,
  iTerm2, WezTerm, kitty, Alacritty and GNOME Terminal all work.

tt-git runs on Linux (x64, arm64), macOS (Apple Silicon) and Windows (x64,
arm64).

## Install script

The install script downloads the latest release for your platform, checks it
against the release's checksums and puts `tt-git` on your `PATH`.

<Tabs syncKey="os">
<TabItem label="Linux and macOS">

```sh
curl -fsSL https://github.com/ThirtyTech/tt-git/releases/latest/download/install.sh | sh
```

It installs into `~/.local/bin`, and tells you how to add that to your
`PATH` if it isn't there already.

</TabItem>
<TabItem label="Windows">

In PowerShell:

```powershell
powershell -ExecutionPolicy Bypass -c "irm https://github.com/ThirtyTech/tt-git/releases/latest/download/install.ps1 | iex"
```

It installs into `%LOCALAPPDATA%\Programs\tt-git\bin` and adds that to your
user `PATH`. Open a new terminal afterwards.

You can update while older copies are still running, even across several
updates. The installer moves the current binary to `tt-git.exe.old`, using
a unique suffix if that backup is still in use. Running copies keep working.
Later installs remove old backups once those copies have exited.

</TabItem>
</Tabs>

Run the same command again to update, or see [Updating](#updating). Two
environment variables change what it does:

| Variable | Does |
|---|---|
| `TTGIT_VERSION` | Install this release, such as `v0.2.0`, instead of the latest |
| `TTGIT_INSTALL_DIR` | Install into this folder instead |

Each [release](https://github.com/ThirtyTech/tt-git/releases) also shows the
commands that install exactly that version.

## Updating

Once tt-git is installed, it can update itself:

```sh
tt-git update
```

It installs the latest release over the tt-git you ran, using the same install
script, and says so if you're already up to date. `tt-git update --check` only
checks, and `tt-git update v0.2.0` installs a particular release. In the UI,
run *Update tt-git* from the [command palette](/git/palette/#updating-tt-git).
Restart tt-git afterwards to use the new version. See
[`tt-git update`](/reference/cli/#tt-git-update).

## Download a release

Every [release](https://github.com/ThirtyTech/tt-git/releases) has an archive
for each platform, named like `tt-git-v0.2.0-linux-x64.tar.gz`:

| Platform | Archive |
|---|---|
| Linux x64 | `linux-x64.tar.gz` |
| Linux arm64 | `linux-arm64.tar.gz` |
| macOS Apple Silicon | `macos-arm64.tar.gz` |
| Windows x64 | `windows-x64.zip` |
| Windows arm64 | `windows-arm64.zip` |

Unpack it and put `tt-git` (`tt-git.exe` on Windows) somewhere on your
`PATH`. `SHA256SUMS.txt` on the release lists each archive's checksum.

<Aside type="note">
	The macOS binary isn't notarized, so if you download it with a browser,
	macOS blocks the first run. Clear the quarantine flag with
	`xattr -d com.apple.quarantine tt-git`. The install script doesn't need
	this.
</Aside>

## Build from source

You need **Rust 1.89 or newer**, from [rustup.rs](https://rustup.rs).

<Steps>

1. Clone the repository:

   ```sh
   git clone https://github.com/thirtytech/tt-git
   cd tt-git
   ```

2. Build and install the `tt-git` binary into `~/.cargo/bin`:

   ```sh
   cargo install --path crates/tt-git
   ```

3. Check that it's on your `PATH`:

   ```sh
   tt-git --version
   ```

</Steps>

## Open a repository

Run `tt-git` inside a repository, or give it a path:

```sh
tt-git                 # the repository in the current directory
tt-git path/to/repo    # another repository
```

Any folder inside a repository works; tt-git finds the top of it the same way
git does. Linked worktrees work too. If the folder isn't in a repository,
tt-git says so and exits.

<Screenshot name="hero" alt="tt-git on a web project: the commit graph on top, the status pane and the branch list below" />

Press <kbd>q</kbd> to quit.

<Aside type="tip">
	Press <kbd>?</kbd> at any time to see the keys for the pane you're in, or
	<kbd>:</kbd> to search every command by name.
</Aside>

## Command line options

| Option | Does |
|---|---|
| `PATH` | Open this repository instead of the current directory |
| `--config FILE` | Read settings from this file instead of the default `config.toml` (see [Configuration file](/configuration/)) |
| `--no-plugins` | Start without plugins and without the plugin API socket |
| `--version`, `--help` | Print the version or help and exit |

`tt-git` also has subcommands for managing plugins and scripting a running
instance, such as `tt-git plugin list` and `tt-git status --json`. They're
listed in [Command line](/reference/cli/).
