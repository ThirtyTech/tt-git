The details pane shows whatever you have selected in full: a commit's message and diff, the list of
files it changed, a stash, or a working-tree file's diff. It follows the selection, so moving through
the graph updates it as you go. In the default layout details is hidden until you ask for it, and
then takes the place of the status and branches panes at the bottom of the screen. Press
<kbd>4</kbd> to focus it from anywhere.

<Screenshot name="details-commit" alt="Details open in place of the bottom row, showing a commit header, message and diffstat" />

## Opening and closing details

| Key | Where | Does |
|---|---|---|
| <kbd>space</kbd> | graph | Shows or hides the selected commit's details |
| <kbd>4</kbd> | anywhere | Opens details and focuses it |
| <kbd>enter</kbd> | graph | Opens the commit fullscreen as changed files beside a diff |
| <kbd>enter</kbd> | Stash tab | Opens the stash fullscreen |
| <kbd>esc</kbd> | graph | Hides details |
| <kbd>esc</kbd> <kbd>space</kbd> | details | Closes details |

Details also closes when you focus a pane it covers, for example <kbd>2</kbd> for status.
Where details opens is part of the [layout](/configuration/layout/): you can give it a permanent pane
of its own instead, so it's always on screen.

<Aside type="tip">
  Nothing loads while details is hidden. When it's open, holding <kbd>j</kbd> in the graph doesn't
  load every commit you pass, only the one you stop on.
</Aside>

## The commit view

The title is `Commit` and the short hash, for example `[4] Commit 59f1c2a`. Below it is what
`git show` prints for the commit:

- the hash, author, committer, dates and parents,
- the full commit message,
- a summary of changed files with `+` and `-` counts,
- and the patch: added lines in green, removed lines in red, hunk headers (`@@ … @@`) in cyan.

A merge commit is shown as what it brought into the branch, compared with its first parent, which is
what you usually want to review. Renamed files show as renames rather than a delete and an add.

Very long diffs stop after 5,000 lines with a count of what's left, so a huge generated file can't
stall tt-git.

Scroll with <kbd>j</kbd> <kbd>k</kbd>, a page at a time with <kbd>ctrl+d</kbd> <kbd>ctrl+u</kbd>
(or <kbd>pagedown</kbd> <kbd>pageup</kbd>), and jump to the top or bottom with <kbd>g</kbd> <kbd>G</kbd>.

## Changed files

<Screenshot name="details-files" alt="Details showing a commit with its changed files listed below the diff" />

Press <kbd>{'}'}</kbd> in details to switch to the changed-files view. The commit header stays at
the top, the selected file's diff fills the middle, and the list of files sits below it under a rule
titled `Files (6)`. Press <kbd>{'}'}</kbd> again to go back to the whole commit.

In this view:

- <kbd>j</kbd> <kbd>k</kbd> pick a file, and its diff shows above. Clicking a file picks it too.
- <kbd>ctrl+d</kbd> <kbd>ctrl+u</kbd> (or <kbd>pagedown</kbd> <kbd>pageup</kbd>) scroll the diff.
- The mouse wheel scrolls the diff when the pointer is over it, and moves through the files when
  it's over the list.
- Renamed files are listed as `old → new`.

Each file's diff loads when you pick it, and stays cached while the view is open. When you move to
another commit in the graph, details stays in the files view and the old list stays up until the new
one arrives, so the layout doesn't jump.

## Fullscreen files and diff

<Screenshot name="details-fullscreen" alt="A commit opened fullscreen with the changed files on the left and the diff on the right" />

Press <kbd>enter</kbd> on a commit in the graph, or double-click it, to open it fullscreen. The changed files are listed on
the left and the selected file's diff fills the right, like a pull request's "Files changed" tab.

<Steps>

1. Select a commit in the graph and press <kbd>enter</kbd>, or double-click it.
2. Pick a file with <kbd>j</kbd> <kbd>k</kbd>, or click it. Scroll its diff with <kbd>pagedown</kbd>
   <kbd>pageup</kbd>, or the mouse wheel over the diff.
3. Press <kbd>esc</kbd> or <kbd>space</kbd> to go back to the graph.

</Steps>

<kbd>+</kbd> also makes the details pane fullscreen from wherever it is, and with the files view on,
fullscreen moves the file list to the left.

## Other things details shows

- **A stash**: on the [Stash tab](/panes/stash/), details shows what the selected stash holds,
  untracked files included.
- **A file's diff**: with the status pane focused, details shows the selected file's staged and
  unstaged changes, titled `Diff` and the path. In the default layout you see this when details has a
  pane of its own; to stage part of a file, use the [staging view](/panes/staging/).
- **Staging**: <kbd>enter</kbd> in the status pane turns details into the
  [staging view](/panes/staging/).
- **Plugin logs**: *Plugin logs* in the [command palette](/git/palette/) lists recent plugin runs in
  details.
- **A plugin pane**: a plugin pane with the `split` placement takes details' place. See
  [Plugin panes](/panes/plugin-panes/).

## Opening a file in your editor

Press <kbd>e</kbd> to open the file you're looking at in your editor, at the line at the top of the
diff. Scroll so the line you want is the top one, then press <kbd>e</kbd>.

| Showing | Opens |
|---|---|
| The changed-files view | The selected file |
| A whole commit or a stash | The file whose diff is at the top of the view; above the first file, the first file |
| A file's diff from the status pane | That file |

Above a file's first hunk, or on an `@@` line, the editor opens at the hunk's first change. A removed
line opens where it was.

When the file is in your working tree, tt-git opens that, not the version in the commit, so you can
edit it. If the file has changed since that commit, the line numbers may have moved and the editor
lands near the line rather than on it.

When it isn't, say because the commit is on a branch you don't have checked out, tt-git opens a
read-only copy of the file as it was in that commit, at the same line, and says
`old.rs isn't in the working tree: opened a read-only copy from 1a2b3c4`. A file the commit deleted
opens as it was just before the commit. The copies go in your temp directory, under
`tt-git/<repo>/<commit>/`, with the file's own path and name, so your editor still recognises the
language. Saving changes to a copy doesn't change anything in the repository. With nothing to open,
such as plugin logs, tt-git says `no file to open here`.

Which editor runs is set in [`[editor]`](/configuration/#editor).

## Links

<Screenshot name="details-link" alt="A commit message with an issue link in the details pane" />

Commit messages often contain links to a pull request or a ticket. Press <kbd>o</kbd>, or
<kbd>ctrl</kbd>+click the link, and tt-git hands the first `http://` or `https://` link in view to a
plugin that knows what to do with it, for example opening it in your browser.

A plugin says which links it handles with a `[[link_handlers]]` pattern in its manifest; see
[Writing a plugin](/plugins/manifest/#link-handlers). If no plugin handles the link, the help bar
says `no plugin handles …` rather than guessing which program should open it.

## Keys

| Key | Does |
|---|---|
| <kbd>j</kbd> <kbd>k</kbd> | Scroll the diff a line (in the files view: pick a file) |
| <kbd>ctrl+d</kbd> <kbd>ctrl+u</kbd>, <kbd>pagedown</kbd> <kbd>pageup</kbd> | Scroll a page |
| <kbd>g</kbd> <kbd>G</kbd> | Top / bottom |
| <kbd>{'}'}</kbd> | Show / hide the changed files |
| <kbd>o</kbd> | Open the link in view with a plugin |
| <kbd>e</kbd> | Open the file in view in your editor |
| <kbd>esc</kbd> <kbd>space</kbd> | Close details |
| <kbd>+</kbd> | Fullscreen and back |

The mouse wheel scrolls details too. In the files view, click a file to show its diff; the wheel
scrolls the diff over the diff and moves through the files over the list.
