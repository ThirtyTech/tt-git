The status pane lists every file you've changed, like lazygit's files panel. From here you stage and
unstage files, commit, amend, discard changes, ignore files, stash, and finish or abort a merge, rebase or
cherry-pick. Its title tells you which branch you're on and how far it is from its upstream. Press
<kbd>2</kbd> to focus it from anywhere.

<Screenshot name="status-pane" alt="The status pane with its title and each kind of file status code called out" />

## What it shows

One row per changed file, with the same two-letter code as `git status -s`. The first letter is the
staged state (the index), the second the unstaged state (the working tree):

```text
M  src/app.rs          staged
 M src/lib.rs          modified, not staged
MM README.md           staged, then changed again
A  docs/new.md         new file, staged
 D old.txt             deleted, not staged
R  a.rs → b.rs         renamed, staged
?? notes.md            untracked
UU src/merge.rs        conflicted
```

The code is colored so you can tell at a glance what's left to do:

- **green**: fully staged, nothing left to stage
- **red**: has changes that aren't staged
- **error color**: a conflict to resolve

Untracked files are listed one by one, even inside new folders. With nothing changed, the pane says
`working tree clean`.

## The folder tree

Press <kbd>&#96;</kbd> to list the files as a tree grouped by folder, like lazygit's file tree, and
again to go back to one row per path. tt-git saves your choice as [`tree`](/configuration/#status)
under `[status]` in your `config.toml`, so the next start opens the same way. The flat list is the
default.

<Screenshot name="status-tree" alt="The status pane as a folder tree: src/ open with api/, components/, hooks/ and styles/ under it, each file listed by name" />

```text
▾ docs/guide/
  ?? intro.md
▾ src/
  ▾ ui/
     M view.rs
  ?? lib.rs
   M main.rs
?? README.md
```

Folders come first, then files, each sorted by name. A folder that holds only another folder shares
its row, as `docs/guide/` does above. A folder's marker and name are colored like a file's code:
green when everything under it is staged, red when something isn't, the error color when it holds
a conflict.

| Key | Does on a folder |
|---|---|
| <kbd>enter</kbd> | Folds the folder (`▸`), or opens it again (`▾`). Double-clicking it does the same. |
| <kbd>space</kbd> | Stages everything under it: `git add -A -- src/`. If it's all staged already, unstages it all |
| <kbd>d</kbd> | Opens the [**Discard all**](#discarding-everything) dialog for just that folder, titled **Discard all in src/** |
| <kbd>i</kbd> | [Ignores](#ignoring-a-file) the folder: **Add /src/ to .gitignore** or **.git/info/exclude** |

<Screenshot name="status-tree-discard" alt="The Discard all in src/styles/ dialog, keeping everything outside src/styles/" />

<kbd>-</kbd> folds every folder and <kbd>=</kbd> opens them all. Folding a folder with the selected
file inside moves the selection to the folder. On a file, every key works as it does in the flat
list. <kbd>e</kbd> and <kbd>b</kbd> need a file, so on a folder they say there's no file to open or
blame. In the flat list, <kbd>-</kbd> and <kbd>=</kbd> say that folders fold in the tree view.

With a folder selected, [details](#other-panes-and-details) shows the folder's diff: its staged
changes, then its unstaged ones, then its untracked files by name.

## The title

```text
[2] Status: tt-git · main → origin/main ↑1 ↓2
```

- the repository's name,
- the branch you're on, or `(detached)`,
- `MERGING`, `REBASING`, `CHERRY-PICKING` or `REVERTING` while one is in progress,
- the upstream branch, and how many commits you're ahead (`↑`) and behind (`↓`) it. Nothing is shown
  for a count of zero.
- `in apps/web/` while the list is [narrowed to a folder](#narrowing-to-a-folder), with how many
  changed files it hides: `+3 outside (1 staged)`.

## Narrowing to a folder

Started in a subfolder of the repository, such as `apps/web/`, press <kbd>.</kbd> to list only the
files changed under it. Press it again to list everything. The
[graph](/panes/graph/#narrowing-to-the-folder-you-started-in) narrows to the same folder at the same
time, and the other way round: <kbd>.</kbd> in either pane, `current folder` in **Filter graph**, or
[`filter_to_cwd`](/configuration/#graph) at startup narrows both. <kbd>esc</kbd> in the graph widens
both again.

While the list is narrowed:

- Conflicted files are always listed, even outside the folder, so you can resolve them.
- <kbd>a</kbd> stages (or unstages) only the files in the folder: `git add -A -- apps/web/`.
- <kbd>D</kbd> discards only changes in the folder. The dialog is titled
  **Discard all in apps/web/**, and keeps *everything outside apps/web/*.
- <kbd>s</kbd> starts on stashing just the folder. <kbd>tab</kbd> still reaches **Everything** and
  the other choices, which cover the whole repository.
- <kbd>c</kbd> and <kbd>A</kbd> still commit everything that's staged, in the folder or not. The
  title's `(1 staged)` warns you when something outside is staged.
- With nothing changed in the folder, the pane says `no changes in apps/web/ (. shows all)`.

## Staging and unstaging files

| Key | Does |
|---|---|
| <kbd>space</kbd> | Stages the selected file if it has unstaged changes, otherwise unstages it |
| <kbd>a</kbd> | Stages everything, or unstages everything if it's all staged already |
| <kbd>enter</kbd> | Opens the file's changes fullscreen, to stage part of it. Double-clicking it does the same. |

In the [folder tree](#the-folder-tree), <kbd>space</kbd> on a folder stages or unstages everything
under it.

Staging a conflicted file marks it resolved. Unstaging works before your first commit too.

To stage only some of a file's changes, a hunk or a line at a time, press <kbd>enter</kbd>. See
[Staging hunks and lines](/panes/staging/).

## Committing and amending

<Screenshot name="status-commit" alt="The Commit message dialog over the screen with a message typed" />

<Steps>

1. Stage what you want in the commit.
2. Press <kbd>c</kbd>. The **Commit message** dialog opens.
3. Type the message and press <kbd>enter</kbd>. <kbd>esc</kbd> cancels.

</Steps>

If nothing is staged, tt-git says `nothing staged to commit (space stages a file, a stages all)`
instead of opening the dialog. An empty message isn't accepted.

Press <kbd>A</kbd> to add what's staged to the last commit, keeping its message. tt-git asks first:
`Amend the last commit with the staged changes, keeping its message?` Press <kbd>y</kbd> or
<kbd>enter</kbd> to go ahead, <kbd>n</kbd> or <kbd>esc</kbd> to cancel.

[Your first commit](/getting-started/first-commit/) walks through the whole thing, push included.

## Discarding changes

Press <kbd>d</kbd> to throw away every change to the selected file. tt-git asks first, since this
can't be undone: `Discard all changes to src/app.rs? This cannot be undone.`

<Screenshot name="status-discard" alt="The Discard changes confirmation dialog" />

What discarding does depends on the file:

- an untracked file is deleted,
- a new file is removed from the index and the working tree,
- a rename is undone on both paths,
- anything else goes back to how it is in the last commit, staged and unstaged changes both.

To discard only part of a file, use the [staging view](/panes/staging/#discarding).

### Discarding everything

Press <kbd>D</kbd> to throw away changes in every file at once, like lazygit's <kbd>D</kbd> menu.
The **Discard all** dialog asks what to discard; <kbd>tab</kbd> (and <kbd>shift+tab</kbd>) moves
between the choices:

| Choice | Throws away | Keeps |
|---|---|---|
| **Everything** | Staged, unstaged and untracked changes: every file goes back to the last commit | Ignored files |
| **Unstaged** | Unstaged changes: each file goes back to what's staged | Staged changes, untracked files |
| **Unstaged + untracked** | Unstaged changes and untracked files | Staged changes |
| **Untracked** | Untracked files and the folders they leave empty | Changes to tracked files |

<Screenshot name="status-discard-all" alt="The Discard all dialog with Everything chosen, counting the files it would throw away" />

The dialog counts what each choice loses and what it keeps, for example
`Lost: 1 staged file, 1 unstaged file, 1 untracked file.` and `Kept: ignored files.` A file with
both staged and unstaged changes counts in both. Press <kbd>y</kbd> or <kbd>enter</kbd> to
discard, <kbd>n</kbd> or <kbd>esc</kbd> to cancel. If the choice has nothing to discard, the
dialog says `Nothing to discard here.` and <kbd>y</kbd> does nothing.

- Files git ignores are never deleted.
- An untracked folder that's a git repository of its own is never deleted. The dialog lists it
  under **Kept** as a nested repository. Submodules aren't touched either: tt-git doesn't recurse
  into them.
- While a merge, rebase, cherry-pick or revert is in progress, <kbd>D</kbd> refuses: finish it
  with <kbd>C</kbd>, abort it with <kbd>X</kbd>, or discard single files with <kbd>d</kbd>.
- With a clean working tree, <kbd>D</kbd> says `nothing to discard`.

<Aside type="caution">
  Discarding can't be undone, and [undo](/git/undo/) (<kbd>z</kbd>) doesn't count it as a step: it
  passes over it to whatever you did before. To keep the changes somewhere first,
  [stash](#stashing) them instead.
</Aside>

## Ignoring a file

Press <kbd>i</kbd> to stop the selected file showing up, as lazygit's <kbd>i</kbd> does. The
**Ignore** list asks where to put it:

<Screenshot name="status-ignore" alt="The Ignore list for src/styles/bell.css, with .gitignore and .git/info/exclude for the file and its folder" />

| Choice | Adds |
|---|---|
| **Add /src/debug.log to .gitignore** | The file to the `.gitignore` at the root of the working tree, which you commit and share |
| **Add /src/debug.log to .git/info/exclude** | The file to `.git/info/exclude`, which stays in this clone |
| **Add /src/ to .gitignore** | The folder the file is in, with everything under it |
| **Add /src/ to .git/info/exclude** | The same folder, in this clone only |

The folder choices only appear for a file inside a folder. Type to narrow the list, then press
<kbd>enter</kbd>; <kbd>esc</kbd> cancels.

tt-git writes the path as a pattern anchored to the root (`/src/debug.log`, `/src/` for a folder),
so it matches only that path and not a file of the same name elsewhere. It creates the file if it's
missing, ends the line with a newline, and leaves the file alone if the pattern is already in it.
In a [linked worktree](/git/worktrees/), `.gitignore` is the one at that worktree's root and
`.git/info/exclude` is the shared one in the main repository's `.git` folder.

Ignoring doesn't hide a file git already tracks. If the file, or anything in the folder, is
tracked, tt-git asks before writing anything: `src/debug.log is tracked, so ignoring it alone won't
hide it. Add it to .gitignore and stop tracking it (git rm --cached)? It stays on disk.` Press
<kbd>y</kbd> to add the pattern and remove the file from the index. A file that's in the last
commit then shows as a staged deletion, which your next commit records; the file itself stays.
Press <kbd>n</kbd> to leave everything as it was.

The status pane refreshes once the pattern is written, and the file drops out of the list.

## Stashing

<Screenshot name="status-stash" alt="The Stash dialog with Unstaged chosen and a message typed" />

Press <kbd>s</kbd> to stash. The **Stash** dialog asks what to stash; <kbd>tab</kbd> (and
<kbd>shift+tab</kbd>) moves between the choices:

| Choice | Stashes |
|---|---|
| **Everything** | Staged, unstaged and untracked changes |
| **Staged** | Only what's staged |
| **Unstaged** | Only the unstaged and untracked changes; the staged ones stay staged |
| **Keep staged** | Everything, but leaves the staged changes in place too |
| *the selected file* | Only that file, untracked or not (both paths of a rename) |
| *the folder*, such as `apps/web/` | Only the changes under it, untracked ones included. Listed first, and picked to start with, while Status is [narrowed to a folder](#narrowing-to-a-folder) |

The message is optional: press <kbd>enter</kbd> with it empty to stash with git's default message.
With nothing changed, tt-git says `nothing to stash`.

**Staged** and **Unstaged** need git 2.35 or newer. Both refuse, leaving everything as it was, when
a file's staged and unstaged changes touch the same lines, since git can't pull them apart. See
[Stash](/panes/stash/#making-a-stash) for the details.

Your stashes appear on the branches pane's [Stash tab](/panes/stash/), where you can pop, apply, drop
and inspect them.

## Opening a file in your editor

Press <kbd>e</kbd> to open the selected file in your editor, at its first change. Where that is
comes from the file's unstaged changes, or its staged ones when there are none. A conflicted file
opens at its first conflict marker (`<<<<<<<`), and a new untracked file at the top.

A file you deleted isn't in the working tree, so there's nothing to open: tt-git says
`notes.txt isn't in the working tree`.

When you quit a terminal editor, tt-git comes back and refreshes, so your edits show up straight
away. Which editor runs, and whether it gets the terminal or a window of its own, is set in
[`[editor]`](/configuration/#editor).

## Blaming a file

Press <kbd>b</kbd> to [blame](/panes/blame/) the selected file: see who last changed each line, when
and in which commit. It opens fullscreen, and <kbd>esc</kbd> comes back to the status pane.

Blame shows the file as it is in your working tree, with lines you haven't committed marked `You`.
A file you deleted is blamed as it was in `HEAD`. An untracked file, or one you've added but never
committed, has no history yet, so tt-git says `notes.txt isn't committed yet: nothing to blame`.

## Merges, rebases and cherry-picks in progress

<Screenshot name="status-conflict" alt="The status pane during a merge with a conflict: MERGING in the title, the banner, a resolved file and a conflicted one" />

When a merge, rebase, cherry-pick or revert stops, the title shows which one, and a banner across the
top of the pane tells you what to do next:

```text
REBASING: stage fixes · C continue · X abort
UU src/merge.rs
```

<Steps>

1. Fix the conflicts in your editor. <kbd>e</kbd> opens the selected file at its first conflict.
2. Stage each fixed file with <kbd>space</kbd>. Staging a conflicted file marks it resolved.
3. Press <kbd>C</kbd> to continue. tt-git keeps the message git prepared, so no editor opens.

</Steps>

<kbd>C</kbd> refuses while a file is still conflicted (`resolve and stage the conflicted files
first`). To give up instead, press <kbd>X</kbd>: tt-git asks, then puts everything back the way it was
before the operation started.

Continue and abort are also in the [command palette](/git/palette/), so you can run them from any
pane. [Merge, rebase and cherry-pick](/git/merge-rebase/) covers the whole flow.

## Other panes and details

With the status pane focused, details follows the selected file and shows its diff, staged changes
first, then unstaged. In the default layout details shares the bottom row with status, so you see
this when you give details a pane of its own in the [layout](/configuration/layout/). Most of the
time <kbd>enter</kbd> into the [staging view](/panes/staging/) is the better way to read a file's
changes. On a folder in the [tree](#the-folder-tree), details shows everything changed under it.

<Aside>
  The status pane refreshes by itself when files change on disk or when you stage from another
  program, ignoring anything git ignores. See [Refreshing](/git/refreshing/).
</Aside>

## Zoom

Press <kbd>+</kbd> in the status pane to turn it into a column down the left of the screen, full
height and about a quarter of the width. The rest of your [layout](/configuration/layout/) moves
over beside it: in the default layout, the graph with branches under it. Press <kbd>+</kbd> again
to go back.

<Screenshot name="status-zoom" alt="The status pane as a full-height column on the left, with the graph and branches beside it" />

Status keeps the focus, so the keys below all work as before. With the column showing:

- <kbd>1</kbd>, <kbd>3</kbd> and <kbd>4</kbd> move to the graph, branches and details and keep
  the column. Details opens where it always does, in place of branches in the default layout.
- <kbd>enter</kbd> on a file opens the [staging view](/panes/staging/) fullscreen as usual, and
  <kbd>esc</kbd> comes back to the column.

## Keys

| Key | Does |
|---|---|
| <kbd>j</kbd> <kbd>k</kbd> <kbd>↓</kbd> <kbd>↑</kbd> | Next / previous file (or folder, in the tree) |
| <kbd>space</kbd> | Stage / unstage the file, or everything in the folder |
| <kbd>enter</kbd> | Stage by hunk or line; on a folder, fold or open it |
| <kbd>a</kbd> | Stage all (or unstage all) |
| <kbd>d</kbd> | Discard changes to the file, or in the folder (asks first) |
| <kbd>D</kbd> | Discard all: everything, unstaged changes, or untracked files (asks first) |
| <kbd>i</kbd> | Ignore the file or its folder (`.gitignore` or `.git/info/exclude`), or the selected folder |
| <kbd>c</kbd> | Commit what's staged |
| <kbd>A</kbd> | Amend the last commit, keeping its message |
| <kbd>s</kbd> | Stash |
| <kbd>e</kbd> | Open the file in your editor at its first change |
| <kbd>b</kbd> | [Blame](/panes/blame/) the file |
| <kbd>.</kbd> | List only the files in the folder tt-git was started in, and back |
| <kbd>&#96;</kbd> | List the files as a [folder tree](#the-folder-tree), or flat (saved to `config.toml`) |
| <kbd>-</kbd> <kbd>=</kbd> | Fold every folder in the tree / open them all |
| <kbd>C</kbd> | Continue a merge, rebase, cherry-pick or revert |
| <kbd>X</kbd> | Abort it (asks first) |
| <kbd>+</kbd> | [Zoom](#zoom): status in a column beside the graph, and back |
