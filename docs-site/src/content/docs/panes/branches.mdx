The branches pane (<kbd>3</kbd>) lists every local and remote branch in one
place. `main`, `origin/main` and `upstream/main` are a single row, the
branches you're working on sit at the top because the list is sorted by
recent activity rather than by name, and a short status column tells you
whether each branch is pushed, behind, or gone from the remote. From here
you check out, create, rename, delete, fetch, merge and rebase. The same
pane has tabs for [tags](/panes/tags/), [merged and unmerged
branches](/panes/merged-unmerged/), the [stash](/panes/stash/) and your
[worktrees](/git/worktrees/#the-worktrees-tab).

<Screenshot name="branches-overview" alt="The branches pane highlighted, with one row per branch and the status and activity columns" />

## The tabs

<kbd>]</kbd> and <kbd>[</kbd> (or <kbd>&#125;</kbd> and <kbd>&#123;</kbd>)
move between the tabs, or click a tab's name in the title. The same keys work
from the [graph](/panes/graph/#all-branches-or-just-the-current-one), which keeps focus:

| Tab | Lists |
|---|---|
| **Branches** | Every local and remote branch, most recently active first. This page. |
| **Tags** | Every tag, newest first. See [Tags](/panes/tags/). |
| **Unmerged** | Branches not yet merged into the base branch. See [Merged and unmerged](/panes/merged-unmerged/). |
| **Merged** | Branches that are. |
| **Stash** | Your stashes, once you have any. See [Stash](/panes/stash/). |
| **Worktrees** | Every worktree of the repository, once there's more than the main one. Open or remove them from here. See [Worktrees](/git/worktrees/#the-worktrees-tab). |

The title shows every tab with its count, the current one underlined, and
the base branch on the tabs that compare against it:

```
Branches 12 · Tags 3 · Unmerged 4 (origin/main) · Merged 9
```

When the pane is too narrow for all of that, only the current tab keeps its
count, so every tab's name still fits.

Each tab keeps its own cursor, so switching away and back returns you to
the same row.

## One row per branch

Local and remote branches with the same name are grouped into one row:

- Each local branch is a row.
- A remote branch joins the local branch that tracks it, so a local `x`
  tracking `origin/feature-x` is one row. If nothing tracks it, it joins the
  local branch with the same name.
- A remote branch with no local counterpart gets a row of its own, shown in
  the remote color.
- `origin/HEAD` and other symbolic refs are left out, since they only repeat
  another branch.

Each row shows a marker (`*` for the checked-out branch, in green), the name,
the status column and how long ago the branch was last active:

```
* main            ✓          2h
  feature/login   ↑2         3h
  fix-typo        local      1d
  release/2.0     origin     4d
  old-spike       gone       3w
```

Moving the selection moves the [graph](/panes/graph/) to that branch's tip.

## Sorted by activity

The list is sorted by when you last did something with each branch, not by
name. A row's activity is the newest of:

- the tip commit's date on each of its refs,
- the last time the branch moved, from its reflog: a commit, a reset, a
  rebase, or a push to the remote branch,
- for local branches, the last time you checked it out.

Checking out an old branch today puts it at the top, even though its newest
commit is old. Fetching doesn't count: a fetch (or a pull, or a
background fetch, tt-git's or your editor's) only tells you about commits, so a remote branch it moves
shows the date of its newest commit, not the time of the fetch. The branches you're working with are always in view without
scrolling or typing. Reading reflogs costs no git processes; see [How tt-git
uses git](/reference/how-it-works/#branches-and-tags).

## The status column

Each row says how the branch relates to its remote:

| Shown | Means | When |
|---|---|---|
| `local` | Local only: nothing on any remote | No upstream, and no remote branch of the same name |
| `origin` / `origin,upstream` | Remote only: you don't have it locally | No local branch; lists every remote that has it |
| `✓` (green) | In sync with its upstream | Upstream set, 0 ahead and 0 behind |
| `↑2` `↓3` `↑2↓3` | Ahead / behind its upstream | git's own ahead and behind counts |
| `gone` (red) | Its upstream was deleted on the remote | Usually seen after a fetch with `--prune` |
| `=origin` | Not tracking, but `origin` has the same name at the same commit | No upstream configured |
| `≠origin` | Not tracking, and `origin`'s same-named branch is elsewhere | No upstream configured |

The column answers "can I delete this?" and "did I forget to push this?" at a
glance: `local` has never been pushed, `gone` was merged and deleted
upstream, and `=origin` is safe to set an upstream for.

## Plugin columns

[Plugins](/plugins/) can add a column of short text next to the branch
names, such as the pull request numbers from the
[GitHub](/plugins/github/) and [Azure DevOps](/plugins/azure-devops/)
plugins. Each plugin's column sits between the name and the status
column. It's as wide as its widest value, up to 10 cells, so the values line
up, and branches without one are left blank:

```
* main                     ✓          2h
  feature/login   !1423    ↑2         3h
  feature/search  !1431    ✓          1d
  fix-typo                 local      1d
```

The columns show on the Branches tab only. A plugin's column goes away when
you disable or remove the plugin. See [Branch
columns](/plugins/api/#branch-columns) for writing one.

## Conflicts with the base branch

tt-git checks in the background whether each branch would merge cleanly into
the [base branch](/panes/merged-unmerged/#the-base-branch), the one the
Unmerged and Merged tabs compare against. A branch whose merge would
conflict gets a red `✗` and the number of files in conflict, right after
its name:

```
* main                    ✓          2h
  feature/login   ✗2      ↑2         3h
  feature/search          ✓          1d
```

No mark means the branch merges cleanly (or is already merged). The column
only appears once some branch conflicts, so the list looks the same as
before while nothing does.

With a conflicting branch selected, the pane's bottom border names the files:

```
╰ ✗ 2 conflicts with origin/main: src/login.rs, src/session.rs ────╯
```

If there are more files than fit, the line is cut off with `…`.

The same mark shows on the [Unmerged](/panes/merged-unmerged/) tab and in
the state of each [worktree](/git/worktrees/#the-worktrees-tab). It's
checked against the base branch's tip, so a branch that conflicts with
`origin/main` may still merge into your local `main` if that's behind.
Nothing is checked out and nothing in the repository changes; see [How
tt-git uses git](/reference/how-it-works/#conflicts-with-the-base).

The check needs git 2.40 or newer. With an older git, or with
`check_merges = false` in the [configuration](/configuration/#branches),
no marks are shown.

## Checking out

<kbd>enter</kbd> or <kbd>space</kbd> checks out the selected branch, and so does double-clicking it.

- A local branch is switched to (`git switch <name>`).
- A remote-only branch gets a local tracking branch, created and checked
  out without asking (`git switch -c <name> --track <remote>/<name>`). If
  several remotes have it, `origin` is preferred. Checking out a remote
  branch nearly always means "give me a local copy of it".

Selecting the branch that's already checked out does nothing.

If another worktree has the branch checked out, git can't check it out here.
tt-git opens that worktree instead, as lazygit does, and says so in the help
bar. See [Worktrees](/git/worktrees/#checking-out-a-branch-another-worktree-has).

## Creating, renaming and deleting

### New branch

<kbd>n</kbd> opens **New branch from &lt;name&gt;**, starting at the selected
branch (the local one if there is one, else the remote). Type a name and
press <kbd>enter</kbd>; tt-git creates it and switches to it.

Press <kbd>tab</kbd> in the dialog to switch from **Branch** to
**Worktree**: the branch is then created in a new worktree under
`.worktrees/<name>` instead of being checked out here. See
[Worktrees](/git/worktrees/).

<Screenshot name="branches-new" alt="The New branch dialog from the branches pane with Worktree selected" />

### New tag

<kbd>T</kbd> opens **New tag at &lt;name&gt;**, to tag the commit the
selected branch points at. See [Tags](/panes/tags/#making-a-tag) for
lightweight and annotated tags, and for pushing and deleting them.

### Rename

<kbd>R</kbd> opens **Rename &lt;name&gt;** with the current name filled in.
Only local branches can be renamed.

### Delete

<kbd>d</kbd> deletes the selected branch, after asking:

- **A local branch** is deleted with `git branch -d`. If git says it isn't
  fully merged, tt-git asks again (**Force delete?**) before running
  `git branch -D`.
- **A remote-only branch** is deleted on the remote: the dialog shows the
  command it will run, `git push <remote> --delete <branch>`.
- The checked-out branch can't be deleted.

Every confirmation takes <kbd>y</kbd> to go ahead and <kbd>n</kbd> or
<kbd>esc</kbd> to cancel.

<Screenshot name="branches-delete" alt="The Delete branch confirmation dialog" />

## Fetching

<kbd>f</kbd> runs `git fetch --all --prune`. `--prune` is what removes
remote branches that were deleted on the remote, and turns the local
branches that tracked them `gone`. See [Push, pull and fetch](/git/remotes/).

## Deleting gone branches

A fetch never deletes your local branches. One whose remote branch was
deleted (usually because its pull request was merged) stays in the list,
marked `gone`. <kbd>D</kbd> cleans them up:

1. It runs `git fetch --all --prune`.
2. If no local branch has a gone upstream, the help bar says
   `✓ fetched all remotes; no branches with a gone upstream`.
3. Otherwise **Delete gone branches** lists them and asks before deleting
   them with `git branch -d`.

   <Screenshot name="branches-prune-gone" alt="The Delete gone branches dialog listing fix/typo-footer" />

4. If git refuses some as not fully merged, **Force delete?** lists those
   and asks again before running `git branch -D`. Answer <kbd>n</kbd> to
   keep them. A branch that was squash-merged or rebased on the remote
   usually ends up here, since its own commits never reached the base.

The checked-out branch, and a branch checked out in another worktree, are
never deleted. The dialog names them as kept.

<kbd>D</kbd> works on the Branches, Unmerged and Merged tabs.

## Fast-forwarding a branch

<kbd>F</kbd> moves the selected local branch up to its upstream without
checking it out, like pulling a branch you aren't on. It runs
`git fetch <remote> <branch>:<branch>`, so it also picks up commits pushed
since your last fetch. The help bar shows
`✓ fast-forwarded feature to origin/feature`, or
`feature is already up to date` when there was nothing new.

It only ever fast-forwards, so it never loses commits and doesn't ask first.
It refuses, with a message saying why, when:

- the branch is checked out: pull it with <kbd>p</kbd> instead
- the branch is checked out in another worktree: pull it there
- it has no upstream, or its upstream is `gone`
- it has commits its upstream doesn't (`↑` in the list), so there's nothing
  to fast-forward, or it has diverged (`↑` and `↓`): check it out and merge
  or rebase instead

A remote-only branch has nothing local to move; check it out instead.

## Pushing a branch

<kbd>P</kbd> pushes the selected local branch to its remote, without
checking it out. Use it for a branch with commits you haven't pushed yet
(`↑` in the list) while you work on another one.

- If the branch has an upstream, tt-git pushes to it:
  `git push <remote> refs/heads/<branch>:<upstream branch>`. That works even
  when the upstream has a different name, or is `gone`, which pushes it
  again.
- If it doesn't, tt-git pushes it to `origin` and sets that as its upstream:
  `git push -u origin refs/heads/<branch>`. With no remote called `origin`,
  it uses the first remote. With no remotes at all, it tells you there's
  nothing to push to.
- On the checked-out branch it does the usual [push](/git/remotes/#push).

A branch checked out in another worktree is pushed the same way; pushing
doesn't touch its files.

It only asks first when the checked-out branch has commits to push too
(it's ahead of its upstream, or has never been pushed). Then a **Push**
dialog names both branches and what each has to push:

- <kbd>y</kbd> or <kbd>enter</kbd> pushes the selected branch.
- <kbd>c</kbd> pushes the checked-out branch instead, as <kbd>P</kbd> does
  in any other pane.
- <kbd>n</kbd> or <kbd>esc</kbd> pushes nothing.

<Screenshot name="branches-push-which" alt="The Push dialog asking whether to push feature/profile-page or the checked-out feature/notifications" />

The help bar shows
`pushing feature → origin/feature`, then `✓ pushed feature →
origin/feature`. If git refuses, for example because the remote has
commits the branch doesn't, the error box shows git's message.

It says why there's nothing to push for a remote-only branch, and for a
branch whose upstream is another local branch.

## Filtering the list

<kbd>/</kbd> starts a filter on the current tab. The title shows what you've
typed (`/flp█`) and the list narrows as you type. Matching ignores case and
works on subsequences, so `flp` finds `feature/login-page`.

- <kbd>↑</kbd> <kbd>↓</kbd> move the selection while you type.
- <kbd>backspace</kbd> deletes a character, <kbd>ctrl+w</kbd> the word
  before the cursor (back to the previous space, as in a shell).
- <kbd>enter</kbd> stops typing and keeps the filter.
- <kbd>esc</kbd> clears it.

<Screenshot name="branches-filter" alt="The branches pane filtered by typing /fpp" />

## Merging and rebasing

- <kbd>M</kbd> merges the selected branch into the current one
  (`git merge --no-edit`).
- <kbd>r</kbd> rebases the current branch onto the selected one,
  non-interactively.

Both ask first. If the result has conflicts, the [status
pane](/panes/status/#merges-rebases-and-cherry-picks-in-progress) shows them
and how to continue or abort. See [Merge, rebase and
cherry-pick](/git/merge-rebase/).

## Resetting to a branch

<kbd>X</kbd> resets the current branch to the selected one: soft, mixed or
hard. On the checked-out branch it resets to its remote branch, such as
`origin/main`, which is how you throw away local commits and match the
remote. Hard asks first and says what's lost. See [Reset](/git/reset/).

## Copying the name

<kbd>c</kbd> copies the branch name to the clipboard. It uses the terminal's
OSC 52 clipboard support, so it also works over SSH.

## Keys

| Key | Does |
|---|---|
| <kbd>enter</kbd> <kbd>space</kbd> | Check out (a remote-only branch gets a tracking branch) |
| <kbd>]</kbd> <kbd>[</kbd> | Next / previous tab |
| <kbd>n</kbd> | New branch from the selection (<kbd>tab</kbd> in the dialog: in a worktree) |
| <kbd>R</kbd> | Rename a local branch |
| <kbd>T</kbd> | New tag at the selection's commit (<kbd>tab</kbd> in the dialog: annotated) |
| <kbd>d</kbd> | Delete (asks; asks again before force-deleting unmerged) |
| <kbd>f</kbd> | `git fetch --all --prune` |
| <kbd>D</kbd> | Fetch, then delete the local branches whose upstream is gone (asks; asks again before force-deleting unmerged) |
| <kbd>F</kbd> | Fast-forward the selected branch to its upstream without checking it out |
| <kbd>P</kbd> | Push the selected branch without checking it out (sets the upstream on the first push; asks which branch when the checked-out one has commits to push too) |
| <kbd>/</kbd> | Filter as you type (<kbd>esc</kbd> clears) |
| <kbd>b</kbd> | Pick the base branch for the Unmerged, Merged and Tags tabs |
| <kbd>M</kbd> | Merge the selection into the current branch |
| <kbd>r</kbd> | Rebase the current branch onto the selection |
| <kbd>X</kbd> | Reset the current branch to the selection (on the checked-out branch: to its remote branch) |
| <kbd>c</kbd> | Copy the branch name |

The keys that work everywhere ([push, pull](/git/remotes/), focus, zoom)
work here too. Every key can be changed; see [Key
bindings](/configuration/keys/).
