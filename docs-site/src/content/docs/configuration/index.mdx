tt-git works with no configuration at all. When you want to change something,
put it in `config.toml`. Every setting is optional, and anything you leave out
keeps its default.

## Where it lives

tt-git reads `config.toml` from the first of these that is set:

| Location | When |
|---|---|
| `$TTGIT_CONFIG_DIR/config.toml` | the variable is set |
| `$XDG_CONFIG_HOME/tt-git/config.toml` | the variable is set |
| `~/.config/tt-git/config.toml` | Linux and macOS |
| `%APPDATA%\tt-git\config.toml` | Windows |

To use a different file for one run, pass it on the command line:

```sh
tt-git --config ~/tt-git-dev.toml
```

If the file doesn't exist, tt-git uses the defaults. The same directory also
holds `plugins.json` and plugin config folders; see
[Plugins overview](/plugins/).

<Aside type="tip" title="Typos are errors">
Unknown keys are reported as errors when tt-git starts, so a misspelled
setting never fails silently.
</Aside>

## Settings

This is every setting, at its default:

```toml title="config.toml"
watch = true        # refresh when files or refs change outside tt-git
mouse = true        # click, wheel, ctrl+click links
syntax = true       # color code by language in diffs, staging and blame
theme = "default"   # color theme: a built-in name, "omarchy", "omarchy:<name>" or your own
theme_background = false  # paint the theme's background instead of leaving the terminal's

[graph]
max_commits = 20000               # loaded at a time; scrolling near the end loads more
max_lanes = 16                    # lanes drawn before collapsing into …
current_includes_upstream = true  # current-branch mode also shows HEAD's upstream
dates = "relative"                # "relative" (3h, 2d) or "clock" (2026-10-17 01:30 PM); graph and blame
lanes = true                      # draw the lanes at startup; L in the graph toggles them
filter_to_cwd = false             # started in a subfolder, show only its commits and files; . toggles it
# message_presets = ["^feat", "^fix"]  # tab steps through these after /; unset, the repo's 8 most used prefixes

[status]
tree = false                      # list changed files as a folder tree; ` toggles it and saves it here

[branches]
unmerged_exclude = ["archive"]    # hide unmerged branches whose name contains any of these
safe_branches = ["master", "main", "production", "prod"]  # never listed on the merged/unmerged tabs
check_merges = true               # mark branches that would conflict with the base branch

[plugins]
pane_release_keys = ["ctrl+\\", "f12"]   # leave or close plugin panes

[editor]
# command = "nvim"   # unset: $VISUAL, $EDITOR, git's core.editor, then notepad / vi
# terminal = true    # unset: worked out from the program

[agent]
command = "claude"   # the agent A starts
placement = "auto"   # a herdr tab inside herdr, else in place of details
# system_prompt = "" # unset: tt-git's own

[ui]
zoom = 100           # desktop app only: how big everything is drawn, in percent
check_for_updates = true  # desktop app only: look for a new release once a day
```

Two more tables, `[layout]` and `[keys]`, have pages of their own:
[Layout](/configuration/layout/) and [Key bindings](/configuration/keys/).
Themes have one too: [Themes](/configuration/themes/).

### Top level

| Setting | Default | What it does |
|---|---|---|
| `watch` | `true` | Watch the working tree and `.git`, and refresh when something changes outside tt-git. See [Refreshing](/git/refreshing/). With `false`, press <kbd>ctrl+r</kbd> to refresh. |
| `mouse` | `true` | Click a pane or row to focus and select it (or a branches tab, a changed file, or a Filter graph entry), double-click a row to do what <kbd>enter</kbd> does on it, scroll the pane under the pointer with the wheel, and <kbd>ctrl</kbd>+click links in the details pane. Turn it off to let your terminal handle the mouse (for example, to select text). In the [desktop app](/desktop/using/#the-mouse) it turns clicks and the wheel off too. |
| `syntax` | `true` | Color code by language in diffs, the [staging view](/panes/staging/) and [blame](/panes/blame/), with added and removed lines on a green or red background. With `false`, code is plain, and diffs show added lines in green and removed lines in red. See [Code colors](/panes/details/#code-colors). |
| `theme` | `"default"` | The color theme: one of the built-in themes such as `"tokyo-night"`, `"omarchy"` to follow Omarchy's current theme, `"omarchy:<name>"` for one of Omarchy's, or your own from `themes/<name>.toml`. *Theme* in the command palette picks one and saves it here. See [Themes](/configuration/themes/). |
| `theme_background` | `false` | Paint the theme's background behind everything, instead of leaving the terminal's. See [The background](/configuration/themes/#the-background). |

### `[graph]`

| Setting | Default | What it does |
|---|---|---|
| `max_commits` | `20000` | How many commits the graph loads at a time. When the selection gets near the end, the next batch of this size loads. |
| `max_lanes` | `16` | How many lanes are drawn. Anything wider collapses into `…`. |
| `current_includes_upstream` | `true` | In current-branch mode (<kbd>a</kbd> in the graph), also show `HEAD`'s upstream, so you can see what you'd push or pull. |
| `dates` | `"relative"` | How dates start out in the graph and in [blame](/panes/blame/#dates): `"relative"` shows ages (`3h`, `2d`), `"clock"` the local date and time (`2026-10-17 01:30 PM`). <kbd>t</kbd> in either switches both. |
| `lanes` | `true` | Draw the lanes left of each commit at startup. With `false`, rows start with their badges and subject. <kbd>L</kbd> in the graph shows or hides them. See [Hiding the lanes](/panes/graph/#hiding-the-lanes). |
| `filter_to_cwd` | `false` | When tt-git is started in a subfolder of the repository, start with the graph showing only the commits that changed it and Status listing only its files. <kbd>.</kbd> in either pane toggles it. `--filter-to-cwd` and `--no-filter-to-cwd` override this for one run. See [Narrowing to the folder you started in](/panes/graph/#narrowing-to-the-folder-you-started-in). |
| `message_presets` | unset | The regexes <kbd>tab</kbd> and <kbd>shift+tab</kbd> step through in the graph's <kbd>/</kbd> message filter. Each one fills in the prompt, so you can edit it before pressing <kbd>enter</kbd>. Unset, they're the 8 subject prefixes (`feat:`, `fix(scope):`) the repository uses most, as `^feat`, `^fix` and so on. A list here replaces them; an empty list leaves just the typed regex. See [Filtering by message](/panes/graph/#filtering-by-message). |

See [Graph](/panes/graph/).

### `[status]`

| Setting | Default | What it does |
|---|---|---|
| `tree` | `false` | List the changed files as a folder tree at startup, instead of one row per path. <kbd>&#96;</kbd> in Status switches between the two and saves your choice here, in the global `config.toml`. A repository's own config file that sets `tree` still wins. See [The folder tree](/panes/status/#the-folder-tree). |

See [Status](/panes/status/).

### `[branches]`

| Setting | Default | What it does |
|---|---|---|
| `unmerged_exclude` | `["archive"]` | The Unmerged tab hides branches whose name contains any of these strings. |
| `safe_branches` | `["master", "main", "production", "prod"]` | Long-lived branches that are never listed on the Merged and Unmerged tabs, matched by exact name on any remote. Set it to `[]` to list them too. |
| `check_merges` | `true` | Check in the background whether each branch and worktree would merge cleanly into the base branch, and mark the ones that conflict with `✗`. Set it to `false` in a repository with so many branches that the check gets in the way. See [Conflicts with the base branch](/panes/branches/#conflicts-with-the-base-branch). |

See [Merged and unmerged](/panes/merged-unmerged/).

### `[plugins]`

| Setting | Default | What it does |
|---|---|---|
| `pane_release_keys` | `["ctrl+\\", "f12"]` | Keys that give focus back to tt-git from a split plugin pane, or close an overlay or popup pane. Written the same way as [key bindings](/configuration/keys/#how-to-write-keys). |

See [Plugin panes](/panes/plugin-panes/).

### `[editor]`

The editor <kbd>e</kbd> opens a file in, from the [status pane](/panes/status/#opening-a-file-in-your-editor),
the [staging view](/panes/staging/#opening-the-file-in-your-editor),
[details](/panes/details/#opening-a-file-in-your-editor) and
[blame](/panes/blame/#copying-and-editing).

| Setting | Default | What it does |
|---|---|---|
| `command` | unset | The editor to run. Unset, tt-git uses the first of `$VISUAL`, `$EDITOR` and git's `core.editor` that is set, else `notepad` on Windows and `vi` elsewhere. Quote a path with spaces: `'"C:\Program Files\Notepad++\notepad++.exe" -multiInst'`. |
| `terminal` | unset | `true` if the editor runs in the terminal, `false` if it opens a window of its own. Unset, tt-git works it out from the program's name, and treats editors it doesn't know as terminal ones. |

tt-git adds the file, and the line when it knows one, in the form the editor
understands:

| Editor | Arguments added |
|---|---|
| vim, nvim, vi, gvim, nano, micro, emacs, emacsclient, kakoune (`kak`), joe, mg, ne | `+12 <file>` |
| VS Code (`code`, `code-insiders`), VSCodium, Cursor, Windsurf | `--goto <file>:12` |
| Helix (`hx`), Zed, Sublime Text (`subl`) | `<file>:12` |
| Notepad++ | `-n12 <file>` |
| JetBrains IDEs (`idea`, `pycharm`, `goland`, `rustrover`, `webstorm`, `clion`, `rider`, `phpstorm`) | `--line 12 <file>` |
| anything else, including Notepad | `<file>` |

The file is a full path, and the editor starts in the repository's root.
To pass the arguments yourself, put `{file}` and `{line}` in `command`.
tt-git then adds nothing, and `{line}` is `1` when there's no line to go to:

```toml
[editor]
command = "code --reuse-window --goto {file}:{line}"
```

A terminal editor gets the whole terminal: tt-git steps aside until you quit
the editor, then comes back and refreshes. A GUI editor (VS Code, Cursor,
Zed, Sublime Text, Notepad, Notepad++, gedit, Kate, TextMate, JetBrains IDEs)
opens in its own window and tt-git keeps running.

<Aside type="caution">
A GUI editor tt-git doesn't recognize is treated as a terminal editor, so
tt-git waits until it exits. Set `terminal = false` for it.
</Aside>

### `[agent]`

The AI agent <kbd>A</kbd> starts from the graph, the staging view and details. See [Agent actions](/git/agents/).

| Setting | Default | What it does |
|---|---|---|
| `command` | `"claude"` | The agent to run, in the repository's root. The prompt is added as its last argument, unless `command` has `{prompt}` (the prompt's text) or `{prompt_file}` (a file holding it) in it. |
| `placement` | `"auto"` | Where it runs. `"auto"`: a new herdr tab when tt-git runs inside [herdr](https://herdr.dev/), else in place of the details pane. `"herdr-tab"` and `"herdr-split"` (a herdr pane beside tt-git's) fall back to the details pane outside herdr; `"details"` always uses it. |
| `system_prompt` | unset | Goes ahead of every prompt, with the same placeholders. Unset, tt-git tells the agent which repository and branch it's in, to read history with git, and not to push or commit unless asked. `""` sends none. |
| `hunk_prompt` | unset | Asking about a [diff hunk](/git/agents/#asking-about-a-hunk), goes after the system prompt, with the same placeholders. Unset, it names the lines, the file and what the diff is of, then gives the lines as a diff. `""` sends none. |
| `actions` | unset | The ready-made actions <kbd>tab</kbd> steps through, as `[[agent.actions]]` tables. Unset, tt-git offers *Resolve conflicts*, *Explain commit*, *Explain branch* and *Review commit*, and from a hunk *Explain change* and *Review change*. Setting it replaces them all. |

Each `[[agent.actions]]` has:

| Field | Required | What it is |
|---|---|---|
| `name` | yes | Shown in the dialog and in the agent's tab or pane title. |
| `prompt` | yes | What the agent is asked. Placeholders such as `{commit}`, `{branch}`, `{base}`, `{conflicts}`, `{log}`, and from a hunk `{file}`, `{lines}` and `{hunk}`, are filled in; see [What the agent is told](/git/agents/#what-the-agent-is-told). |
| `description` | no | One line shown under the input while the action is selected. |
| `when` | no | `"always"` (the default); `"merging"`: only while a merge, rebase, cherry-pick or revert is stopped, and then first; or `"hunk"`: only when asking about a diff hunk, where only these are offered. |

```toml
[[agent.actions]]
name = "Write release notes"
description = "user-facing notes for this branch"
prompt = "Write release notes for what {branch} adds since {base}:\n{log}"
```

### `[ui]`

Settings for the [desktop app](/desktop/). The terminal app ignores them.

| Setting | Default | What it does |
|---|---|---|
| `zoom` | `100` | How big the desktop app draws everything, in percent: text, spacing, menus and dialogs together, as a browser zooms. From `50` to `300`; a value outside that is taken as the nearest end. [Zooming](/desktop/using/#zoom) in the app saves the new value here. Only the global config file sets it, for every window; a repository's own file can't. |
| `check_for_updates` | `true` | Look for a new tt-git release once a day and say in the help bar when there is one. `false` stops it; *Check for Updates…* still works. See [Updating](/desktop/install/#updating). Read from the global config file when the app starts. |

## Per-repository config

A repository can have settings of its own that override `config.toml`. They
go in one of two files, which take the same settings as `config.toml`:

| File | For |
|---|---|
| `.tt-git.toml` in the repository's root | Settings to share. Commit it and everyone who opens the repository with tt-git gets them. |
| `.git/tt-git.toml` | Your own settings for this repository. It isn't committed, and every worktree of the repository reads it. |

tt-git reads `config.toml` first, then `.tt-git.toml`, then
`.git/tt-git.toml`. A setting in a later file replaces the same setting in an
earlier one. Tables combine key by key, so a repository that only sets
`max_lanes` keeps the rest of your `[graph]` settings. Lists are replaced
whole, not added to, and so is the whole `[layout]`.

For example, a `.tt-git.toml` that gives a large repository its own message
presets and loads fewer commits:

```toml title=".tt-git.toml"
[graph]
max_commits = 5000
message_presets = ["^feat", "^fix", "^perf"]
```

`--config` replaces only `config.toml`. The repository's files still apply on
top of the file you pass.

The files are read when tt-git starts in the repository, and again when you
[open another worktree](/git/worktrees/), which gets that worktree's
`.tt-git.toml`. To pick up a change, restart tt-git. `mouse` only takes effect
for the repository tt-git started in.

A mistake in either file is reported when tt-git starts, naming the file, the
same way as one in `config.toml`.

Either file can set anything `config.toml` can, including the programs tt-git
runs: `[editor]`, `[agent]`, `[plugins]` and `[[keys.command]]` bindings. A
team can commit its agent actions or plugin keys in `.tt-git.toml` along with
the code.

To see which files apply to a repository, run
[`tt-git config path`](/reference/cli/#tt-git-config-path).

### The base branch

One setting lives in the repository's git config rather than a tt-git file:
the base branch the Merged, Unmerged and Tags tabs compare against. Press
<kbd>b</kbd> in the branches pane to pick it, and tt-git saves it as
`tt-git.baseBranch` in that repository's own git config (`.git/config`).
Nothing is written to your global git config. See
[The base branch](/panes/merged-unmerged/#the-base-branch).

## Logs

The UI owns the terminal, so tt-git writes its log to a file:
`<state>/logs/tt-git.log`. `<state>` is the first of these that is set:

| Location | When |
|---|---|
| `$TTGIT_STATE_DIR` | the variable is set |
| `$XDG_STATE_HOME/tt-git` | the variable is set |
| `~/.local/state/tt-git` | Linux and macOS |
| `%APPDATA%\tt-git` | Windows |

Plugin state lives under the same directory, in `plugins/<id>/`. The
[desktop app](/desktop/) logs to `tt-git-gui.log` in the same `logs`
folder, and keeps its window position and recent repositories in
[`gui.json`](/desktop/using/#what-it-remembers) there.

Set the level with `TTGIT_LOG`. It takes an
[`EnvFilter`](https://docs.rs/tracing-subscriber/latest/tracing_subscriber/filter/struct.EnvFilter.html)
string, and the default is `info`:

```sh
TTGIT_LOG=debug tt-git
TTGIT_LOG=tt_git_core=trace tt-git
```

Every running tt-git appends to the same file. When it has grown past 10 MB,
the next tt-git to start renames it to `tt-git.log.1` (replacing an older one)
and starts a fresh `tt-git.log`.

Plugin runs have a log of their own; see
[Plugin logs](/plugins/#plugin-logs).
