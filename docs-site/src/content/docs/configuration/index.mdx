tt-git works with no configuration at all. When you want to change something,
put it in `config.toml`. Every setting is optional, and anything you leave out
keeps its default.

## Where it lives

tt-git reads `config.toml` from the first of these that is set:

| Location | When |
|---|---|
| `$TTGIT_CONFIG_DIR/config.toml` | the variable is set |
| `$XDG_CONFIG_HOME/tt-git/config.toml` | the variable is set |
| `~/.config/tt-git/config.toml` | Linux and macOS |
| `%APPDATA%\tt-git\config.toml` | Windows |

To use a different file for one run, pass it on the command line:

```sh
tt-git --config ~/tt-git-dev.toml
```

If the file doesn't exist, tt-git uses the defaults. The same directory also
holds `plugins.json` and plugin config folders; see
[Plugins overview](/plugins/).

<Aside type="tip" title="Typos are errors">
Unknown keys are reported as errors when tt-git starts, so a misspelled
setting never fails silently.
</Aside>

## Settings

This is every setting, at its default:

```toml title="config.toml"
watch = true        # refresh when files or refs change outside tt-git
mouse = true        # click, wheel, ctrl+click links

[graph]
max_commits = 20000               # loaded at a time; scrolling near the end loads more
max_lanes = 16                    # lanes drawn before collapsing into …
current_includes_upstream = true  # current-branch mode also shows HEAD's upstream

[branches]
unmerged_exclude = ["archive"]    # hide unmerged branches whose name contains any of these
safe_branches = ["master", "main", "production", "prod"]  # never listed on the merged/unmerged tabs

[plugins]
pane_release_keys = ["ctrl+\\", "f12"]   # leave or close plugin panes
```

Two more tables, `[layout]` and `[keys]`, have pages of their own:
[Layout](/configuration/layout/) and [Key bindings](/configuration/keys/).

### Top level

| Setting | Default | What it does |
|---|---|---|
| `watch` | `true` | Watch the working tree and `.git`, and refresh when something changes outside tt-git. See [Refreshing](/git/refreshing/). With `false`, press <kbd>ctrl+r</kbd> to refresh. |
| `mouse` | `true` | Click a pane or row to focus and select it, scroll the pane under the pointer with the wheel, and <kbd>ctrl</kbd>+click links in the details pane. Turn it off to let your terminal handle the mouse (for example, to select text). |

### `[graph]`

| Setting | Default | What it does |
|---|---|---|
| `max_commits` | `20000` | How many commits the graph loads at a time. When the selection gets near the end, the next batch of this size loads. |
| `max_lanes` | `16` | How many lanes are drawn. Anything wider collapses into `…`. |
| `current_includes_upstream` | `true` | In current-branch mode (<kbd>a</kbd> in the graph), also show `HEAD`'s upstream, so you can see what you'd push or pull. |

See [Graph](/panes/graph/).

### `[branches]`

| Setting | Default | What it does |
|---|---|---|
| `unmerged_exclude` | `["archive"]` | The Unmerged tab hides branches whose name contains any of these strings. |
| `safe_branches` | `["master", "main", "production", "prod"]` | Long-lived branches that are never listed on the Merged and Unmerged tabs, matched by exact name on any remote. Set it to `[]` to list them too. |

See [Merged and unmerged](/panes/merged-unmerged/).

### `[plugins]`

| Setting | Default | What it does |
|---|---|---|
| `pane_release_keys` | `["ctrl+\\", "f12"]` | Keys that give focus back to tt-git from a split plugin pane, or close an overlay or popup pane. Written the same way as [key bindings](/configuration/keys/#how-to-write-keys). |

See [Plugin panes](/panes/plugin-panes/).

### Per-repository settings

One setting lives in each repository rather than in `config.toml`: the base
branch the Merged, Unmerged and Tags tabs compare against. Press <kbd>b</kbd>
in the branches pane to pick it, and tt-git saves it as `tt-git.baseBranch` in
that repository's own git config (`.git/config`). Nothing is written to your
global git config. See [The base branch](/panes/merged-unmerged/#the-base-branch).

## Logs

The UI owns the terminal, so tt-git writes its log to a file:
`<state>/logs/tt-git.log`. `<state>` is the first of these that is set:

| Location | When |
|---|---|
| `$TTGIT_STATE_DIR` | the variable is set |
| `$XDG_STATE_HOME/tt-git` | the variable is set |
| `~/.local/state/tt-git` | Linux and macOS |
| `%APPDATA%\tt-git` | Windows |

Plugin state lives under the same directory, in `plugins/<id>/`.

Set the level with `TTGIT_LOG`. It takes an
[`EnvFilter`](https://docs.rs/tracing-subscriber/latest/tracing_subscriber/filter/struct.EnvFilter.html)
string, and the default is `info`:

```sh
TTGIT_LOG=debug tt-git
TTGIT_LOG=tt_git_core=trace tt-git
```

Every running tt-git appends to the same file. When it has grown past 10 MB,
the next tt-git to start renames it to `tt-git.log.1` (replacing an older one)
and starts a fresh `tt-git.log`.

Plugin runs have a log of their own; see
[Plugin logs](/plugins/#plugin-logs).
