The `[layout]` table in [`config.toml`](/configuration/) decides where each
pane goes. It's a tree: each node is either a pane or a split that holds more
nodes.

## The default layout

{/* screenshot: default layout at 1080p; graph (top 70%) and the status | branches row outlined, the bottom row marked "details opens here" */}

```toml title="config.toml"
[layout]
split = "rows"
children = [
  { pane = "graph", size = 70 },
  { split = "columns", details = true, children = [{ pane = "status" }, { pane = "branches" }] },
]
```

The graph spans the top 70% of the screen. Status and branches sit side by
side below it. That bottom row is marked `details = true`, so when you open
details (<kbd>space</kbd> on a commit, or <kbd>4</kbd>), details takes the
row's place until you close it.

## How the tree works

Each node has either `pane` or `split`, never both.

| Key | On | Means |
|---|---|---|
| `pane` | a leaf | One of `graph`, `status`, `branches` or `details`. |
| `split` | a split | `rows` stacks its children top to bottom; `columns` puts them side by side, left to right. |
| `children` | a split | The nodes inside it. A split needs at least one; a pane can't have any. |
| `size` | any node | A percentage of the parent split, from 1 to 99. Children without a size share whatever is left. |
| `details` | any node | `true` marks the node details opens in place of. |

The rules tt-git checks when it loads the layout:

- `graph`, `status` and `branches` each appear exactly once.
- Details is placed once: either as a `details` pane of its own, or by marking
  one node `details = true`. Not both.
- The node marked `details = true` can't contain the graph.
- The sizes in a split can't add up to more than 100, or to 100 when the split
  also has children without a size.

A layout that breaks a rule is reported as an error when tt-git starts, with
what's wrong.

## Where details opens

You have two choices.

**Details opens on demand.** Mark a node `details = true`, as the default
layout does. Details stays hidden until you press <kbd>space</kbd> on a commit
in the graph, or <kbd>4</kbd>. It then takes that
node's place until you press <kbd>space</kbd> again (in the graph or details),
<kbd>esc</kbd>, or focus a pane it covers. Nothing loads into details while
it's hidden.

**Details is always on screen.** Give it a `{ pane = "details" }` leaf of its
own instead. It then follows the selection in the graph and branches pane all
the time.

<Aside type="tip">
Whichever you choose, <kbd>enter</kbd> on a commit opens it fullscreen, with
the changed files on the left and the selected file's diff on the right. See
[Details](/panes/details/).
</Aside>

### Zoom

<kbd>+</kbd> zooms whatever layout you use: the focused pane (details, or else
the graph) fills the screen, and the next <kbd>+</kbd> goes back. With the
graph zoomed, <kbd>space</kbd> opens details below it at full width, and closes
it again.

## Examples

### The four-pane layout

{/* screenshot: four-pane layout at 1080p; status and branches stacked on the left third, graph over details on the right, each pane outlined */}

Earlier versions of tt-git kept details on screen all the time, in a
four-pane layout. To get it back:

```toml title="config.toml"
[layout]
split = "columns"
children = [
  { size = 33, split = "rows", children = [{ pane = "status", size = 40 }, { pane = "branches" }] },
  { split = "rows", children = [{ pane = "graph", size = 65 }, { pane = "details" }] },
]
```

Status (40%) and branches are stacked in the left third. The graph (65%) and
details are stacked on the right.

### Details beside the graph

Details opens in place of the right column, next to a full-height graph:

```toml title="config.toml"
[layout]
split = "columns"
children = [
  { pane = "graph", size = 60 },
  { split = "rows", details = true, children = [{ pane = "status" }, { pane = "branches" }] },
]
```

### Details in place of one pane

`details = true` can go on a single pane, too. Here details covers only the
branches pane and leaves status visible:

```toml title="config.toml"
[layout]
split = "rows"
children = [
  { pane = "graph", size = 70 },
  { split = "columns", children = [{ pane = "status" }, { pane = "branches", details = true }] },
]
```

## Moving between panes

The layout also decides what <kbd>ctrl+h</kbd>, <kbd>ctrl+j</kbd>,
<kbd>ctrl+k</kbd> and <kbd>ctrl+l</kbd> do: they focus the pane to the left,
below, above or to the right of the focused one, wherever it is on screen.
<kbd>1</kbd> to <kbd>4</kbd> and <kbd>tab</kbd> work the same in any layout.
See [Moving around](/getting-started/navigation/).
