`tt-git-gui` is tt-git as a desktop app. It runs in a window of its own on
Windows, macOS and Linux instead of in a terminal. Under the window it's the
same program: the same panes, the same keys, the same config and plugins.
Everything else on this site applies to it.

<Screenshot name="gui-overview-windows" alt="The tt-git desktop app on Windows: the tt-git, Repository, View and Graph menus in the title bar, the commit graph on top, the status pane and the branch list below, and the help bar along the bottom" caption="The desktop app on Windows, on the same project as the rest of this site's screenshots." />

## Built with GPUI

The desktop app is drawn with [GPUI](https://gpui.rs/), the UI framework the
[Zed](https://zed.dev/) editor is built on. GPUI draws every frame on the
GPU (Direct3D 11 on Windows, Metal on macOS, Vulkan on Linux), so the graph,
diffs and blame scroll smoothly, at any size and zoom. The title bar, menus
and right-click menus come from
[gpui-component](https://github.com/longbridge/gpui-kit); the panes are
tt-git's own, in the same [theme](/configuration/themes/) as the terminal
app. By default they're drawn as rounded cards with headers in your system's
UI font; the [terminal style](/desktop/using/#style) draws them in the same
monospace boxes as the terminal app.

GPUI only draws. What the app does, from the keymap to the git commands it
runs, is shared with the terminal app, which is why the two can't drift
apart. [How it's built](/desktop/architecture/) shows the crates and how the
two front ends share them.

The desktop app adds what a window can do and a terminal can't:

- **Menus** listing every command with its key.
- **Right-click** a pane for a menu of what you can do on the row you
  clicked.
- **Drag the borders** between panes to resize them.
- **One window per repository.** Open another repository and it gets its own
  window.
- A **start window** when you open it outside a repository, with the
  repositories you opened last.
- **Notifications** when a fetch brings new commits while you're in
  another window, if you [turn them on](/desktop/using/#notifications).
- **The taskbar** on Windows shows a push, pull or fetch
  [still running](/desktop/using/#taskbar-progress), and with notifications
  on, a [badge](/desktop/using/#the-taskbar-badge) for new commits or
  conflicts. Its [jump list](/desktop/using/#jump-list) has your recent
  repositories.
- **The Dock** on macOS has your recent repositories in its
  [menu](/desktop/using/#dock-menu), and with notifications on, a
  [badge](/desktop/using/#the-dock-badge) for new commits or conflicts.

## On each system

The app is the same on all three. What changes is where the menus go and
how the window fits in with the desktop.

<Tabs syncKey="os">
<TabItem label="Windows">

The window draws its own title bar: the tt-git icon, the menus (**tt-git**,
**Repository**, **View** and one for the focused pane), the window's title,
and the minimize, maximize and close buttons.

<Screenshot name="gui-menu-windows" alt="The Graph menu open in the desktop app's title bar on Windows, listing the graph's commands with their keys" caption="The menus live in the title bar on Windows." />

Install it with the setup program or the zip; see
[Install and open](/desktop/install/).

</TabItem>
<TabItem label="macOS">

The menus are in the macOS menu bar at the top of the screen, as in any Mac
app, each item with its key after its name. The window's title bar has the
traffic-light buttons, then the tt-git icon and the window's title.

<Screenshot name="gui-overview-macos" alt="The desktop app on macOS, with the traffic-light buttons, the tt-git icon and the window's title above the graph, the Status pane and the Branches pane" caption="On macOS the title bar has only the window's buttons and title; the menus are in the menu bar." />

## What's the same as in the terminal

The desktop app runs the same app as `tt-git`, so you don't learn anything
twice:

- **The panes.** [Graph](/panes/graph/), [Details](/panes/details/),
  [Status](/panes/status/), [staging](/panes/staging/),
  [Blame](/panes/blame/), [Branches](/panes/branches/) and its tabs, in the
  same places and doing the same things.
- **The keys.** Every key works as in the terminal, in every pane and
  dialog, with the same defaults. The keymap is the only place keys are
  bound: the menus, the right-click menus, the help bar, the help popup
  (<kbd>?</kbd>) and the [command palette](/git/palette/) all show the keys
  from it. See [Keyboard shortcuts](/reference/keys/).
- **Your config.** The desktop app reads the same
  [`config.toml`](/configuration/), the repository's own `.tt-git.toml` and
  `.git/tt-git.toml`, your [key bindings](/configuration/keys/), your
  [layout](/configuration/layout/) and your [theme](/configuration/themes/).
  A key you rebind for one is rebound for both.
- **Plugins.** The same installed [plugins](/plugins/) load, with their
  actions, event hooks, startup commands and
  [panes](/panes/plugin-panes/). Plugin panes and the
  [agent pane](/git/agents/) are terminals drawn inside the window.
- **git.** It runs the `git` on your `PATH` for everything, as the terminal
  app does (see [How tt-git uses git](/reference/how-it-works/)).

<Aside type="note">
	Keys pressed with <kbd>cmd</kbd> on macOS or the Windows key are left to
	the system and never reach tt-git. Bindings use <kbd>ctrl</kbd>,
	<kbd>alt</kbd> and <kbd>shift</kbd>, as in the terminal.
</Aside>
