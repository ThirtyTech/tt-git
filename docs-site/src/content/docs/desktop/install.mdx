## Requirements

- **git 2.31 or newer** on your `PATH`, as for the
  [terminal app](/getting-started/install/#requirements).
- Windows (x64), macOS (Apple Silicon) or Linux (x64, arm64). There's no
  desktop app for Windows on arm64 yet; the terminal app runs there.
- On Linux, a graphics driver with Vulkan, and the system libraries listed
  [below](#linux).

## Download a release

The desktop app is a download of its own on each
[release](https://github.com/ThirtyTech/tt-git/releases), named
`tt-git-gui-<version>-<platform>`, such as
`tt-git-gui-v0.10.0-linux-x64.tar.gz`. The terminal app's archives
(`tt-git-<version>-<platform>`) don't contain it.

Every desktop app download also carries `tt-git`, next to `tt-git-gui`.
Plugins in the app run that one (see [Plugins](/desktop/using/#plugins)),
so leave it where it is.

<Aside type="caution">
	Release builds may be unsigned. Windows and macOS then warn you, or
	block the app, the first time you start it. Each tab below says how to
	let it run.
</Aside>

<Tabs syncKey="os">
<TabItem label="Windows">

Pick one of two downloads:

- **`tt-git-gui-<version>-windows-x64-setup.exe`**, an installer. It
  installs for your user without admin rights, into
  `%LOCALAPPDATA%\Programs\tt-git`, adds **tt-git** to the Start menu, and
  offers a desktop shortcut. Uninstall it from **Settings → Apps**.
- **`tt-git-gui-<version>-windows-x64.zip`**, a folder holding
  `tt-git-gui.exe` and `tt-git.exe`. Unpack it anywhere and run
  `tt-git-gui.exe`.

If the build is unsigned, SmartScreen stops the first run with *Windows
protected your PC*. Click **More info**, then **Run anyway**.

Neither puts `tt-git` on your `PATH`. For `tt-git` in a terminal, install
the terminal app with the [install script](/getting-started/install/#install-script).

</TabItem>
<TabItem label="macOS">

Download **`tt-git-gui-<version>-macos-arm64.dmg`** and open it. Drag
**tt-git** to the Applications folder beside it, then open it from
Applications or Spotlight.

If the build is unsigned, macOS blocks the first launch. Right-click
**tt-git** in Applications and choose **Open**, then **Open** again. Or,
after macOS has blocked it once, allow it in **System Settings → Privacy &
Security** and open it again.

The app holds both binaries in `tt-git.app/Contents/MacOS`: `tt-git-gui`
and `tt-git`. For `tt-git` in a terminal, link to the app's copy:

```sh
sudo ln -s /Applications/tt-git.app/Contents/MacOS/tt-git /usr/local/bin/tt-git
```

or install the terminal app on its own with the
[install script](/getting-started/install/#install-script).

</TabItem>
<TabItem label="Linux">

Pick one of two downloads, for `linux-x64` or `linux-arm64`:

- **`tt-git-gui-<version>-linux-<arch>.tar.gz`**, a tree to unpack into
  `~/.local` (or `/usr/local` for every user, with `sudo`):

  ```sh
  tar -xzf tt-git-gui-v0.10.0-linux-x64.tar.gz --strip-components=1 -C ~/.local
  ```

  That puts `tt-git-gui` and `tt-git` in `bin/`, `tt-git.desktop` in
  `share/applications/` and the icons in `share/icons/hicolor/`. **tt-git**
  then shows up in your app launcher. The launcher runs `tt-git-gui` from
  your `PATH`, so `~/.local/bin` must be on your session's `PATH`, not only
  your shell's.
- **`tt-git-gui-<version>-linux-<arch>.AppImage`**, one file. Make it
  executable and run it:

  ```sh
  chmod +x tt-git-gui-v0.10.0-linux-x64.AppImage
  ./tt-git-gui-v0.10.0-linux-x64.AppImage
  ```

  It still uses the system's Wayland or X11, Vulkan and fontconfig
  libraries.

</TabItem>
</Tabs>

## Updating

The desktop app updates itself. In the **tt-git** menu, choose **Check for
Updates…**, right under *About tt-git*. *Update tt-git* in the
[command palette](/git/palette/#updating-tt-git) does the same.

<Screenshot name="gui-check-for-updates" alt="The tt-git menu open from the title bar on Windows: About tt-git, Check for Updates… (highlighted), Theme, Plugin logs and Quit" />

It looks on GitHub for the latest release, with *checking for a tt-git
update…* in the help bar:

- If you have it, a dialog says *tt-git is up to date*.
- If there's a newer one, a dialog says *tt-git v0.10.0 is available* and
  asks first. Choose **Update and Restart**, or **Later** (or press
  <kbd>esc</kbd>) to leave it.

<Screenshot name="gui-update-available" alt="The dialog on Windows: tt-git v0.9.0 is available. You have 0.8.0. Updating downloads it, replaces this copy and restarts tt-git: every window closes and opens again on its repository. Buttons: Update and Restart, Later" />

**Update and Restart** downloads the new release (the help bar says
*downloading tt-git v0.10.0…*), checks it against the release's
`SHA256SUMS.txt`, and puts it in place of the copy you're running. Then
every tt-git window closes and opens again on the same repository, in
every copy of the app you have open, so a second copy started from the
Start menu or a terminal comes back too. A copy that only showed the
[start window](#the-start-window) comes back on the start window.

Which download it uses, and how it's put in place, depends on how you
installed the app:

| Installed from | Downloads | Then |
|---|---|---|
| The Windows installer | `…-windows-x64-setup.exe` | Waits until every window has closed, runs the new installer without its wizard, and opens the windows again. Settings → Apps shows the new version. An install for all users asks for admin rights. |
| The Windows zip | `…-windows-x64.zip` | Replaces `tt-git-gui.exe` and `tt-git.exe` in their folder. Windows can't overwrite a running program, so the old ones are renamed to `tt-git-gui.exe.old` and `tt-git.exe.old` and deleted the next time the app starts. |
| The macOS .dmg | `…-macos-arm64.dmg` | Replaces the whole `tt-git.app`, where it is. |
| A Linux AppImage | `…-linux-<arch>.AppImage` | Replaces the AppImage file. |
| The Linux tarball | `…-linux-<arch>.tar.gz` | Replaces `bin/tt-git-gui` and `bin/tt-git`. Under `/usr/local` that needs write permission there, so it fails for a normal user: update that copy by hand. |

The folder it's in must be one you can write to. If the download, the
checksum or the swap fails, an error popup says why, starting *updating
tt-git to v0.10.0 failed*, and the copy you have stays as it was.

A window with a [terminal editor](/desktop/using/#editing-files) running
still asks before it closes. Choose **Cancel** and that copy of the app
keeps running the old version; the others restart. With the Windows
installer, nothing is installed until every copy has closed, and after 5
minutes it gives up and leaves the old version.

Some copies can't update themselves. The dialog then says why and offers
**Open Download Page**, which opens the release on GitHub:

- one built from source with cargo: *build it again instead*;
- one installed by a package manager (in `/usr/bin`): update it there;
- a copy not laid out the way a release download installs it, or on a
  platform without a desktop app download (Windows on arm64).

### Checking in the background

Once a day, the app looks for a new release by itself (the first time 30
seconds after it starts). When there's one, the help bar says so, once per
release:

<Screenshot name="gui-update-notice" alt="The right end of the help bar: tt-git v0.9.0 is out: tt-git ▸ Check for Updates installs it" />

It never installs anything without asking: choose **Check for Updates…**
for that. The time of the last check is kept in `gui-update.json` in the
[state folder](/configuration/#logs), shared by every copy of the app, so
two windows don't both go online. A check that fails (offline, say) waits
a day too. To turn it off, set [`check_for_updates = false` in
`[ui]`](/configuration/#ui).

On macOS, `tt-git update` refuses to replace the `tt-git` inside the app,
even through a link on your `PATH`: *tt-git is part of the desktop app
(/Applications/tt-git.app); update the app from the release's download
instead*.

### Linux

The desktop app draws with the GPU through Vulkan and uses the system's
font, keyboard and window libraries. Most desktops have them already. On
Debian or Ubuntu:

```sh
sudo apt install libvulkan1 mesa-vulkan-drivers libfontconfig1 libfreetype6 \
  libwayland-client0 libxkbcommon0 libxkbcommon-x11-0 libx11-xcb1 libxcb1 \
  libasound2 libzstd1
```

It runs on both Wayland and X11. The folder picker behind *Open repository*
needs the desktop portal (`xdg-desktop-portal` and the one for your
desktop, such as `xdg-desktop-portal-gtk` or `-kde`).

## Build from source

You need **Rust 1.89 or newer**. On Linux, also the development packages
GPUI builds against (`.github/workflows/gui.yml` lists them for Ubuntu):

```sh
sudo apt install gcc g++ clang libfontconfig-dev libfreetype-dev libwayland-dev \
  libxkbcommon-dev libxkbcommon-x11-dev libx11-xcb-dev libxcb1-dev \
  libssl-dev libzstd-dev libasound2-dev libvulkan1
```

Then, from a clone of the repository:

```sh
cargo install --path crates/tt-git-gui
cargo install --path crates/tt-git      # for plugins
```

The first build takes several minutes: the GPUI toolkit is large. A build
from source has no app bundle or `.desktop` file, so on macOS and Wayland
the window has no icon. `crates/tt-git-gui/packaging/` has the scripts the
release uses to make them.

## Starting it

Start it from your launcher, or from a terminal inside a repository or with
a path:

```sh
tt-git-gui                  # the repository in the current directory
tt-git-gui path/to/repo     # another repository
tt-git-gui ~/src/a ~/src/b  # two windows
```

Any folder inside a repository works, and so do linked worktrees. The
window's title is `<repo> - tt-git`.

It takes the same options as [`tt-git`](/reference/cli/#tt-git), and
several repositories at once:

| Option | Does |
|---|---|
| `PATH`… | Open these repositories instead of the current directory, each in a window of its own |
| `--config FILE` | Read settings from this file instead of the default `config.toml` |
| `--no-plugins` | Start without plugins and without the plugin API socket |
| `--filter-to-cwd`, `--no-filter-to-cwd` | Started in a subfolder, narrow the graph and Status to it, or don't |
| `--version`, `--help` | Print the version or help and exit |

`tt-git-gui` has no subcommands. Use `tt-git` for `tt-git plugin list` and
the others in [Command line](/reference/cli/).

A config file tt-git can't read stops it before any window opens, with the
error printed in the terminal. It logs to `<state>/logs/tt-git-gui.log`,
next to the terminal app's `tt-git.log` (see [Logs](/configuration/#logs)).

## The start window

Started outside a repository, from a launcher say, tt-git opens a small
start window instead:

<Screenshot name="gui-start-windows" alt="The start window: Open folder… at the top, then the recent repositories, the last one greyed out and marked (missing)" />

- **Open folder…** shows the system's folder picker. Pick one or more
  repositories, and each opens in its own window.
- **Recent** lists the last 10 repositories you opened, newest first. Click
  one to open it. One whose folder is gone says *(missing)*; opening it
  fails, says why, and drops it from the list.

| Key | Does |
|---|---|
| <kbd>up</kbd> <kbd>down</kbd>, <kbd>k</kbd> <kbd>j</kbd> | Pick a recent repository |
| <kbd>enter</kbd> | Open it |
| <kbd>o</kbd> | Open folder… (also <kbd>ctrl+o</kbd>, or <kbd>cmd+o</kbd> on macOS) |
| <kbd>q</kbd> <kbd>esc</kbd> | Close the window |

The start window closes once a repository opens. If you named a folder on
the command line that isn't in a repository, it opens with a message saying
so.

## Opening another repository

From a repository window, run **Open repository** from the
[command palette](/git/palette/) or the **Repository** menu. It shows the
folder picker, and each folder you pick opens in a new window. A repository
that already has a window isn't opened twice: its window comes to the front.
A folder that isn't in a repository shows an error popup.

*Open repository* has no key. To give it one, bind `open_repository` (see
[Key bindings](/configuration/keys/#commands)):

```toml title="config.toml"
[keys.global]
open_repository = "ctrl+o"
```

In the terminal app the palette doesn't list it, and a key bound to it only
says *opening another repository needs the desktop app*.

Each window is a repository of its own: its own panes, file watcher, plugins
and API socket. Closing the last window quits the app.
