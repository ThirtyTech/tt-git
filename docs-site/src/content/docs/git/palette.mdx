## Opening the palette

Press <kbd>:</kbd> or <kbd>ctrl+p</kbd> from any pane. A **Commands** box
opens near the top of the screen with a search line and the list below it.

## What it lists

The list depends on which pane is focused. In order, it shows:

1. **The focused pane's commands**, such as *Stage/unstage*, *Commit* and
   *Stash* in the status pane, *Checkout*, *New branch* and *Fetch* in the
   branches pane, or *Open* and *Remove* on its Worktrees tab.
2. **Plugin actions** for what you're looking at. An action shows up when its
   plugin offers it everywhere, or for the focused pane: commits in the graph,
   branches in the branch list, files in the status pane.
3. **Plugin panes**, as *Open &lt;title&gt;*.
4. **Common commands** that aren't already listed: [*Ask agent*](/git/agents/), continue or abort a merge
   or rebase, [undo](/git/undo/), pull, push, refresh, switch the graph between all and current
   branch, focus a pane, zoom, *Theme*, *Plugin logs*, *Update tt-git* (not in the desktop app), *About* and help.
5. In the [desktop app](/desktop/) only, *Open repository*, then *Zoom in*,
   *Zoom out* and *Reset zoom*, last. *Open repository* opens another
   repository in a window of its own; see
   [Opening another repository](/desktop/install/#opening-another-repository).
   The zoom commands are described in [Zoom](/desktop/using/#zoom).

The right side of each row shows its key, if it has one, so the palette
doubles as a way to learn the keys. For a plugin action it shows the
plugin's name.

*Plugin logs* is only in the palette. It opens a list of recent plugin runs
with their exit codes and output; see [Plugins](/plugins/#plugin-logs).

*Theme* is only in the palette too. It lists the color themes and shows each
one as you move through the list; <kbd>enter</kbd> keeps it and saves it to
`config.toml`, <kbd>esc</kbd> goes back. See [Themes](/configuration/themes/).

## Updating tt-git

*Update tt-git* is only in the palette (bind `self_update` to give it a key).
It checks GitHub for a newer release, with *checking for a tt-git update…* in
the help bar while it looks:

- If you have the latest release, the help bar says
  *tt-git 0.3.0 is up to date*.
- If there's a newer one, it asks first: *tt-git v0.4.0 is out (you have
  0.3.0). Download and install it now?* Press <kbd>y</kbd> to install it or
  <kbd>n</kbd> to leave it.

The install runs in the background while you keep working. The help bar
shows a spinner beside *update tt-git to v0.4.0*, with each line the install
script prints next to it. When it's done it reads *✓
installed tt-git v0.4.0; restart tt-git to use it*. If the check or the install
fails (no network, say), an error popup shows why, with the script's output.
The [desktop app](/desktop/) leaves *Update tt-git* out of its palette and
menus, since the install script doesn't know its downloads. Run from a key,
it says *update the desktop app by downloading the latest release* with the
address. See [Updating the desktop app](/desktop/install/#updating).

It does the same as [`tt-git update`](/reference/cli/#tt-git-update), and
refuses in the same cases, such as a tt-git run from a cargo build.

## About tt-git

*About* opens a dialog with the version of tt-git you're running, the
developer, the address of the [GitHub repository](https://github.com/thirtytech/tt-git),
and [Ratatui](https://ratatui.rs/), the library the terminal app is drawn
with. The addresses are plain text: most terminals open one when you
<kbd>ctrl</kbd>-click or <kbd>cmd</kbd>-click it. The dialog also points to
the [desktop app](/desktop/), `tt-git-gui`, which has the same panes and
keys in a window of its own and shows the same dialog from its
[menu](/desktop/using/#about).

<Screenshot name="about" alt="The About tt-git dialog: the version, the developer, the GitHub address, a line about the desktop app tt-git-gui, and Ratatui's address" />

<kbd>esc</kbd>, <kbd>enter</kbd>, <kbd>q</kbd> or <kbd>space</kbd> closes it;
other keys do nothing while it's open. *About* is only in the palette (bind
`about` to give it a key).

## Searching

Type to narrow the list. The match ignores case and the letters only have to
appear in order, so `nbr` finds *New branch* and `plo` finds *Plugin logs*.

| Key | Does |
|---|---|
| <kbd>↓</kbd> / <kbd>ctrl+n</kbd> | Next entry |
| <kbd>↑</kbd> / <kbd>ctrl+p</kbd> | Previous entry |
| <kbd>backspace</kbd> | Delete the last character typed |
| <kbd>enter</kbd> | Run the selected entry |
| <kbd>esc</kbd> | Close the palette |

In [blame](/panes/blame/#going-to-a-line), the title reads *Commands or a line number*: type a
number, with or without a leading `:`, and the list becomes a single *Go to line 42* entry that
<kbd>enter</kbd> runs. So <kbd>:</kbd> `42` <kbd>enter</kbd> goes to line 42, as in vim.

<Aside type="tip">
	Run a plugin action often? Give it a key in your config instead. See
	[Binding plugin actions](/configuration/keys/#binding-plugin-actions).
</Aside>

The same kind of list is used elsewhere in tt-git, for example to pick a
[base branch](/panes/merged-unmerged/#the-base-branch), and it works the
same way.
