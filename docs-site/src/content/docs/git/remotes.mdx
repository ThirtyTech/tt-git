The status title always shows how the current branch stands against its
upstream: `main → origin/main ↑1 ↓2` is one commit to push and two to pull.
The [branches pane](/panes/branches/#the-status-column) shows the same for
every branch.

<Screenshot name="remotes-title" alt="The status pane title showing the upstream and one commit ahead" />

## Push

Press <kbd>P</kbd> (shift+p) from any pane to push the current branch.

- If the branch has an upstream, tt-git runs `git push`.
- If it doesn't, tt-git pushes it to `origin` and sets that as its upstream,
  like `git push -u origin HEAD`. With no remote called `origin`, it uses the
  first remote. With no remotes at all, it tells you there's nothing to push
  to.

While it runs, the help bar shows `pushing main → origin/main` with a
spinner (see [While it runs](#while-it-runs)), then `✓ pushed main →
origin/main`. If git refuses, for example because the remote has commits you
don't, the error box shows git's message. Pull, then push again.

In the branches pane, <kbd>P</kbd> pushes the selected branch instead, so
you can push a branch without checking it out; see
[Pushing a branch](/panes/branches/#pushing-a-branch). On the Worktrees tab
it pushes the selected worktree's branch. If the current branch has commits
to push as well, it asks which one to push: <kbd>y</kbd> the selected
branch, <kbd>c</kbd> the current one.

Pushing a branch doesn't push tags. On the branches pane's Tags tab,
<kbd>P</kbd> pushes the selected tag instead; see [Tags](/panes/tags/#pushing-a-tag).

## Pull

Press <kbd>p</kbd> from any pane. tt-git runs `git pull --no-edit`, so
whether it merges or rebases is up to your git config (`pull.rebase`,
`pull.ff`), and a merge commit keeps git's default message instead of
opening an editor.

The help bar shows `pulling origin/main into main` while it runs, then
`✓ pulled origin/main into main`.

If the pull stops on a conflict, the status pane shows a banner and the
conflicted files. See [Resolving conflicts](/git/merge-rebase/#resolving-conflicts).

## Fetch

Press <kbd>f</kbd> in the branches pane to run `git fetch --all --prune`. It
fetches every remote and removes remote branches that were deleted on the
server. A local branch whose upstream was deleted then shows `gone` in red in
the branch list, which usually means it was merged and can be deleted.
The fetch itself never deletes local branches; press <kbd>D</kbd> in the
branches pane to fetch and then delete them, after asking. See [Deleting gone
branches](/panes/branches/#deleting-gone-branches).

<Aside>
	In the graph, <kbd>f</kbd> opens the author and file filter instead. Fetch
	from the branches pane (<kbd>3</kbd>, then <kbd>f</kbd>).
</Aside>

A fetch that brings nothing new doesn't reload the graph.

The help bar shows `fetching all remotes` while it runs, then
`✓ fetched all remotes`.

## Background fetch

While a repository is open, tt-git also fetches every remote on its own
every minute, so the remote branches, the ahead and behind counts and the
[new commit notifications](/desktop/using/#notifications) stay current
without you pressing <kbd>f</kbd>. It runs the same
`git fetch --all --prune`, in the terminal app and the desktop app. Set
`interval` under [`[fetch]`](/configuration/#fetch) to change how often, or
`0` to turn it off. On battery it fetches less often, and in battery saver or
on a metered connection not at all: see [On battery and metered
connections](#on-battery-and-metered-connections).

A background fetch is quiet:

- **Nothing on screen.** No spinner, no `✓` and no taskbar progress. The
  branches and graph refresh when it brings something new.
- **No sign-in.** It never asks for a password, not even through Git
  Credential Manager's window or an SSH askpass program. A remote that
  needs one makes the background fetch fail.
- **Failures are only logged**, in tt-git's log file, never as an
  **Error** box. It tries again at the next interval.

It waits its turn:

- **Any fetch counts.** The interval runs from the repository's last
  fetch, whoever made it: you with <kbd>f</kbd>, `git fetch` in a terminal,
  or your editor.
- **One fetch per repository.** Several windows on one repository, or on
  its worktrees, share one background fetch instead of each making their
  own.
- **Not while you're syncing.** It doesn't start while your own fetch, pull
  or push runs. If you press <kbd>f</kbd> while a background fetch runs,
  yours waits for it and shows its result, as if you'd started it. If the
  background fetch failed, yours then runs as usual.

Commits an agent makes in another [worktree](/git/worktrees/) are already in
the repository, so they show without a fetch.

### On battery and metered connections

Background fetches back off to save battery and data:

| When | Background fetch |
|---|---|
| On mains power, on an unmetered connection | Every interval (1 minute) |
| On battery | Every three intervals (3 minutes) |
| Battery saver (Windows), Low Power Mode (macOS) or the power-saver profile (Linux) | Paused |
| A metered connection | Paused |

tt-git checks again every 30 seconds, so fetching picks up as soon as you
plug in or join an unmetered network. Fetches you start with <kbd>f</kbd>,
<kbd>p</kbd> or <kbd>D</kbd> always run.

What counts as metered depends on the system:

- **Windows**: a network set as metered (**Settings > Network & internet**),
  or a connection that's roaming or over its data limit.
- **macOS**: a connection the system marks expensive (a personal hotspot,
  cellular) or one in Low Data Mode.
- **Linux**: a connection NetworkManager says is metered, set by you or
  guessed (a phone's hotspot).

To fetch at the interval regardless, set `conserve = false` under
[`[fetch]`](/configuration/#fetch).

## Fast-forward a branch you aren't on

Press <kbd>F</kbd> on a branch in the branches pane to bring it up to its
upstream without checking it out. It fetches the upstream and moves the
branch only if that's a fast-forward. See [Fast-forwarding a
branch](/panes/branches/#fast-forwarding-a-branch) for when it refuses.

## While it runs

Push, pull and fetch run in the background, so you can keep working. The
right end of the help bar shows what git is doing, in the key color, with a
spinner and, after the first second, how long it has been running:

<Screenshot name="remotes-pushing" alt="The help bar showing a spinner, pushing feature/notifications → origin/feature/notifications, and 2s" />

- **Done**: it says what happened, like `✓ pushed main → origin/main`, in
  green. After five seconds it fades to grey, so a fresh result stands out
  from an old one.
- **Failed**: the spinner goes and an **Error** box shows git's message.
- **Pressed again**: pressing <kbd>P</kbd> while a push runs (or
  <kbd>p</kbd> during a pull, <kbd>f</kbd> during a fetch, <kbd>P</kbd> on
  a branch or tag being pushed) says `already pushing` instead of starting a second
  one.
- **Several at once**: a fetch and a push together show `fetching · pushing`.
- **Other messages**: something else that happens meanwhile, such as
  `copied …`, shows beside the spinner for three seconds and then makes
  way for it.

Other git operations (commit, checkout, stash and so on) show the same
spinner with their name while they run, usually too briefly to notice.

## Credentials

tt-git runs git with its terminal prompts turned off
(`GIT_TERMINAL_PROMPT=0`), so a username or password prompt can't hang the
screen. Git still uses your credential helper (Git Credential Manager, the
macOS keychain, `gh auth` and so on) and SSH still uses your `ssh-agent`.
If git needs a credential it can't get on its own, the push, pull or fetch
fails with git's message. A [background fetch](#background-fetch) never
opens your credential helper's sign-in window either. Run the same command once in a terminal, or set up
a credential helper, and it'll work from tt-git after that.
