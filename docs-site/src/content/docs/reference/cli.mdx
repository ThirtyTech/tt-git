`tt-git` on its own opens the UI. With a subcommand, it does that one thing
and exits; those subcommands are also how [plugins](/plugins/api/) talk to a
running tt-git. `tt-git --help`, or `--help` after any subcommand, prints the
same information.

## tt-git

```sh
tt-git [PATH] [--config FILE] [--no-plugins] [--filter-to-cwd | --no-filter-to-cwd]
```

Opens the UI on a repository.

| Argument | |
|---|---|
| `PATH` | The repository to open, or any folder inside it. Default: the current directory. |
| `--config FILE` | Read this config file instead of the [default one](/configuration/#where-it-lives). The repository's own [`.tt-git.toml` and `.git/tt-git.toml`](/configuration/#per-repository-config) still apply on top of it. |
| `--no-plugins` | Don't load plugins or open the API socket. |
| `--filter-to-cwd` | Started in a subfolder of the repository (or with `PATH` one), start with the graph and Status [narrowed to it](/panes/graph/#narrowing-to-the-folder-you-started-in), whatever [`filter_to_cwd`](/configuration/#graph) says. |
| `--no-filter-to-cwd` | Start with the whole repository shown, even with `filter_to_cwd = true`. |
| `--version`, `-V` | Print the version. |
| `--help`, `-h` | Print help. |

If `PATH` isn't in a git repository, tt-git says so and exits with status 1.

While it runs, tt-git sets the terminal title to `<repo> - tt-git`, where
`<repo>` is the working tree's folder name. Terminal multiplexers and their
plugins can use it to tell tt-git is open in a pane.

```sh
tt-git                       # the repository you're in
tt-git ~/src/website         # another one
tt-git --no-plugins          # without plugins, for example to rule one out
cd apps/web && tt-git --filter-to-cwd   # just this project's commits and files
```

## tt-git-gui

```sh
tt-git-gui [PATH]... [--config FILE] [--no-plugins] [--filter-to-cwd | --no-filter-to-cwd]
```

Opens the [desktop app](/desktop/) on a repository. It takes the same
arguments as `tt-git`, plus more than one `PATH` (each opens in a window of
its own), and has no subcommands. Outside a repository, it opens
the [start window](/desktop/install/#the-start-window) instead of exiting.
It logs to `<state>/logs/tt-git-gui.log`. It updates itself from its
**Check for Updates…** menu item: see [Updating](/desktop/install/#updating).
`tt-git update` updates only the terminal app.

## Commands that need a running tt-git

Most subcommands talk to a running tt-git through its API socket. They find it
in `TTGIT_SOCKET_PATH`, which every plugin process has, or in `--socket`:

| Option | |
|---|---|
| `--socket ADDRESS` | The socket of the tt-git to talk to. Default: `$TTGIT_SOCKET_PATH`. |

Without either, they stop with "no running tt-git". These are marked
**socket** below.

Three commands read the repository directly instead, and take `--repo`:

| Option | |
|---|---|
| `--repo PATH` | The repository. Default: `$TTGIT_REPO_PATH`, then the current directory. |

## tt-git plugin

Manage plugins. See [Plugins overview](/plugins/).

| Command | |
|---|---|
| `tt-git plugin install SOURCE [--ref REF] [--yes]` | Install from GitHub. `SOURCE` is `owner/repo`, or `owner/repo/subdir…` for a plugin in a subfolder. `--ref` picks a branch, tag or commit (default: the repository's default branch). Shows what will run and asks first, unless `--yes` (`-y`). |
| `tt-git plugin update [TARGET…] [--yes]` | Update plugins installed from GitHub: the ones named by id or `owner/repo`, or all of them. Skips unchanged plugins and linked ones. |
| `tt-git plugin uninstall TARGET` | Remove an installed plugin, by id or `owner/repo`. |
| `tt-git plugin link PATH [--disabled]` | Register a local plugin directory (or its manifest file), for development. No build step runs. `--disabled` registers it turned off. |
| `tt-git plugin unlink ID` | Remove a plugin from the registry. Its files are kept. |
| `tt-git plugin list [--json] [--plugin ID]` | List installed plugins: id, version, whether it's enabled, disabled or unavailable, where its manifest is, and any warnings. |
| `tt-git plugin enable ID` | Turn a plugin on. |
| `tt-git plugin disable ID` | Turn a plugin off, keeping it installed. |
| `tt-git plugin config-dir ID` | Print the plugin's config directory. |

### tt-git plugin action **socket**

| Command | |
|---|---|
| `tt-git plugin action list [--plugin ID]` | List actions as JSON. |
| `tt-git plugin action invoke ACTION [--plugin ID]` | Run an action. `ACTION` is the qualified id, or the local id with `--plugin`. Prints `{log_id}`. |

### tt-git plugin log **socket**

| Command | |
|---|---|
| `tt-git plugin log list [--plugin ID] [--limit N]` | Recent plugin command runs as JSON, newest first, with exit codes and output. `--limit` defaults to 50. |

### tt-git plugin pane **socket**

| Command | |
|---|---|
| `tt-git plugin pane open --plugin ID --entrypoint ID [options]` | Open a `[[panes]]` entry point. Prints `{pane_id}`. |
| `tt-git plugin pane focus PANE_ID` | Focus an open pane. |
| `tt-git plugin pane close PANE_ID` | Close an open pane. |

Options for `pane open`:

| Option | |
|---|---|
| `--placement PLACEMENT` | `overlay`, `popup`, `split`, `tab` or `zoomed`. Default: the manifest's. |
| `--width SIZE`, `--height SIZE` | Popup size: cells, or `N%`. |
| `--env KEY=VALUE` | Extra environment for the pane. Repeat for more. |
| `--focus` / `--no-focus` | Focus the pane when it opens (default), or not. |

See [Plugin panes](/panes/plugin-panes/).

## tt-git ui **socket**

Control the running UI.

| Command | |
|---|---|
| `tt-git ui notify MESSAGE` | Show a message in the help bar. |
| `tt-git ui error MESSAGE` | Show an error popup. |
| `tt-git ui refresh` | Reload everything. |
| `tt-git ui focus PANE` | Focus a pane: `status`, `branches`, `graph` or `details`. |

## tt-git events **socket**

```sh
tt-git events [--event NAME]…
```

Stream events from the running tt-git as JSON lines, one per event, until you
stop it. `--event` limits it to the named events; repeat it for more. See
[Events](/plugins/events/).

## tt-git api **socket**

```sh
tt-git api METHOD [PARAMS_JSON]
```

Send any [socket method](/plugins/api/#methods) and print the result as JSON:

```sh
tt-git api repo.info
tt-git api ui.notify '{"message":"hi"}'
```

## tt-git status

```sh
tt-git status [--json] [--repo PATH]
```

Print the working tree status, one `XY path` line per file, the same codes as
`git status -s`. `--json` prints the full status: branch, upstream,
ahead/behind and every entry.

## tt-git branch list

```sh
tt-git branch list [--json] [--repo PATH]
```

Print the [unified branch list](/panes/branches/#one-row-per-branch), most
recently active first, with `*` on the checked-out branch. `--json` adds each
branch's refs, dates and `state` (the status column).

## tt-git branch decorate

```sh
tt-git branch decorate [--plugin ID] [BRANCH=TEXT]...
tt-git branch decorate [--plugin ID] --clear
```

Set the text a plugin shows in its [column of the branch
list](/panes/branches/#plugin-columns), replacing everything that plugin set
before. `--plugin` defaults to `TTGIT_PLUGIN_ID`, so a plugin doesn't need it.
With no `BRANCH=TEXT`, or with `--clear`, the plugin's column goes away.
Needs a running tt-git (`TTGIT_SOCKET_PATH`, or `--socket`), and the plugin
must be installed and enabled. Text is cut to 10 cells.

```sh
tt-git branch decorate feature/login=!1423 fix/typo=!1431
```

## tt-git config path

```sh
tt-git config path [--repo PATH]
```

Print the config files tt-git reads for a repository, one per line, in the
order it reads them: `config.toml`, then the repository's `.tt-git.toml`, then
its `.git/tt-git.toml`. Later files win. Files that don't exist are marked
`(not found)`. Outside a repository it prints only `config.toml`. See
[Per-repository config](/configuration/#per-repository-config).

```sh
$ tt-git config path
/home/me/.config/tt-git/config.toml
/home/me/src/website/.tt-git.toml
/home/me/src/website/.git/tt-git.toml  (not found)
```

## tt-git update

```sh
tt-git update [VERSION]
tt-git update --check
```

Update tt-git to the latest release. It finds the newest release on GitHub,
and if that's newer than the one you're running, downloads that release's
[install script](/getting-started/install/#install-script) and runs it, with
the script's output shown as it goes. The script checks the download against
the release's checksums and replaces the binary you ran, in the folder it's
in. If you're already on the latest release, it says so and stops.

| Argument | |
|---|---|
| `VERSION` | Install this release instead, such as `v0.2.0` or `0.2.0`, even if it's older than yours. |
| `--check` | Only say whether there's a newer release. Can't be combined with `VERSION`. |

Restart tt-git afterwards to use the new version. A tt-git that's running
keeps working: on Windows the old `tt-git.exe` is renamed to `tt-git.exe.old`
first, with a unique suffix if an earlier backup is still in use. This also
works across several updates with older copies still open. Later installs
remove backups once those copies have exited.

It needs `curl`, plus `sh` on Linux and macOS or Windows PowerShell on
Windows. All three come with the operating system. It refuses a tt-git that
was built with cargo and run from its `target` folder; build that one again
instead. On macOS it also refuses the `tt-git` inside the
[desktop app](/desktop/install/#updating) (`tt-git.app/Contents/MacOS`),
even run through a link: update the app from its download instead.

```sh
tt-git update --check    # is there a newer release?
tt-git update            # install it
tt-git update v0.2.0     # go back to v0.2.0
```

The command palette has the same thing as *Update tt-git*. See
[Command palette](/git/palette/#updating-tt-git).

## Environment variables

| Variable | |
|---|---|
| `TTGIT_CONFIG_DIR` | Where `config.toml`, `plugins.json` and plugin config folders live. See [Configuration file](/configuration/#where-it-lives). |
| `TTGIT_STATE_DIR` | Where logs and plugin state live. See [Logs](/configuration/#logs). |
| `TTGIT_LOG` | The log level, as an `EnvFilter` string. Default `info`. |
| `TTGIT_SOCKET_PATH` | The socket the **socket** commands use. |
| `TTGIT_REPO_PATH` | The repository `status`, `branch list` and `config path` read. |

<Aside type="caution">
If you start a terminal from inside a tt-git plugin pane, it inherits
`TTGIT_SOCKET_PATH` and `TTGIT_REPO_PATH`, so the commands above act on that
tt-git and its repository.
</Aside>
